\subsection{Zero Sorry Policy}

\texttt{sorry} is Lean~4's escape hatch---it axiomatically asserts any proposition as true.
A proof containing \texttt{sorry} is not a proof; it is a claim. Our CI pipeline
(\texttt{lake build} followed by \texttt{grep -r sorry}) rejects any commit containing
\texttt{sorry} in a theorem statement. Lemmas may use \texttt{sorry} during development
on feature branches, but merges to \texttt{main} require zero \texttt{sorry}.

\subsection{Proof Maintenance}

Proofs break when the model changes. We maintain proofs alongside the Go implementation:
when the consensus protocol changes, the Lean model must be updated first and all proofs
must re-compile before the Go code is modified. This is enforced by CI: the Lean build
gate blocks the Go build gate.
