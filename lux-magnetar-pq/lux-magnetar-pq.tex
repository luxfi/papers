\begin{abstract}
We specify \emph{Magnetar}, the hash-based post-quantum signature
primitive of the Lux Polaris cert profile. Magnetar's headline
primitive is a \emph{per-validator standalone} construction: each
validator $i$ holds an independent FIPS 205 SLH-DSA keypair
$(sk_i, pk_i)$ \cite{fips205}, produces a single-party deterministic
signature $\sigma_i$ on the consensus message, and the consensus
layer collects $N$ signatures into a \emph{ValidatorAggregateCert}
that verifies under any unmodified FIPS 205 verifier. There is no
distributed key generation, no dealer, no aggregator, and no
threshold reconstruction step. Each $\sigma_i$ is byte-identical to
what a single-party FIPS 205 $\textsc{SignDeterministic}$ would
produce on $(sk_i, \mu, \mathit{ctx})$ --- this is the
\emph{byte-identity claim} pinned by
$\textsc{TestMagnetar\_Wire\_FIPS205Verifiable}$
(\texttt{ref/go/pkg/magnetar/wire\_test.go}:166--220), which routes
through the \texttt{ValidatorSign} primary primitive, strips the
canonical MAGS/MAGG wire envelope to recover the raw FIPS 205
payload, and feeds it to
\texttt{cloudflare/circl/sign/slhdsa.Verify} \cite{circl} with no
Magnetar code path on the verifier side. All three SHAKE parameter
sets (SHAKE-192s, SHAKE-192f, SHAKE-256s) pass under
\texttt{-count=1} and \texttt{-race}.

\textbf{Why per-validator and not threshold.} SLH-DSA is hash-based
and admits no FROST-style linear share-aggregation identity
\cite{cosmin2021,sphincs,fips205}. Cozzo-Smart (EUROCRYPT 2019) and
Bonte-Smart-Tan (2023) establish that every internal SHAKE/SHA-2
evaluation in an HBS scheme is a non-linear function of the secret
seed; producing a single FIPS 205-shaped signature from $t$ shares
requires either reconstructing the seed (a dealer or aggregator in
the trusted computing base) or running a full multi-party
computation over the SHA-256/SHAKE hash tree (open research, on
the order of $10^4$ hash invocations per signature under MPC). For
\emph{public-BFT} consensus the architecturally correct primitive
is therefore $N$ standalone signatures collected at the consensus
layer; the per-validator-standalone construction shipped here is
the canonical hash-based instantiation of that pattern.

\textbf{Composition.} The $N \times |\sigma|$ on-wire cost of a
$K=21$ Lux Polaris quorum at SHAKE-192s is $\sim 332$~KiB. The
Z-Chain Groth16 rollup compresses this to $\sim 192$~B before the
certificate hits long-term storage. The rollup is a separate
primitive (lux-zchain spec); the Magnetar wire codec presents the
parallel-slices \texttt{(Signers, PubKeys, Sigs)} shape that maps
directly onto the rollup witness layout.

The companion artefact is \texttt{luxfi/magnetar} v0.5.2
\cite{magnetargo}, with the wire codec MAGS/MAGG and the stateless
\texttt{VerifyBytes} dispatcher landing in commit \texttt{1c84519}
on 2026-05-31. The reference implementation is pure Go, backed by
\texttt{cloudflare/circl/sign/slhdsa} v1.6.3 \cite{circl} for the
underlying FIPS 205 primitive, with the same constant-time posture
the circl maintainers ship. Magnetar joins Pulsar (Module-LWE)
\cite{lp073pulsarpaper} and Corona (Ring-LWE) \cite{lp104corona}
as the three independent legs of the Lux Polaris maximum-assurance
post-quantum cert profile; the three primitives draw on
algorithmically distinct families (M-LWE / R-LWE / hash-based) so
no single algorithmic break collapses the conjunction.

\textbf{Threshold-form availability.} The threshold form of
Magnetar --- Shamir-VSS over the SLH-DSA scheme seed with
reveal-and-aggregate semantics, and a true threshold-HBS
construction (THBS) per McGrew et al. ePrint 2019/793 with
selected-element reconstruction --- ships in the same artefact
under \texttt{ref/go/pkg/thbs/}. Both forms are
\emph{TEE-required by policy}: the dealer (THBS v1) or aggregator
(reveal-and-aggregate) holds master secret material in memory and
must run inside hardware-attested confidential compute (AMD
SEV-SNP, Intel TDX, or equivalent). The threshold forms are
appropriate for M-Chain bridge custody and A-Chain confidential
compute, where a TEE-attested host is in the TCB by deployment
policy. They are explicitly NOT public-BFT-safe and are documented
in Appendix~\ref{app:thbs} for completeness; production
public-consensus deployments use the per-validator standalone
primitive of this paper's main body.
\end{abstract}

\section*{Reproducibility}
\textbf{Source code.} \texttt{github.com/luxfi/magnetar} at tag
\texttt{v0.5.2} (canonical wire codec + stateless verifier commit
\texttt{1c84519}; per-validator standalone primary primitive
\texttt{111df91}; honest-aggregate transitional path
\texttt{5100ffc}; v0.3 Tier-A documentation shape commits
\texttt{572147c} through \texttt{db6c252}).\\
\textbf{Build.} \texttt{cd ref/go \&\& GOWORK=off go build ./... \&\&
GOWORK=off go test -short ./pkg/magnetar/...}. The race-detector
($-$race) is supported but skips the SLH-DSA heavy paths via the
\texttt{raceEnabled} build-tag pattern; race-on runs cover the cheap
unit tests (shamir, transcript, types, wire).\\
\textbf{Headline regression.}
\texttt{go test -count=1 -run TestMagnetar\_Wire\_FIPS205Verifiable
./ref/go/pkg/magnetar/...}
pins byte-identity between \texttt{ValidatorSign} output (after
MAGS envelope strip) and
\texttt{cloudflare/circl/sign/slhdsa.Verify} across all three
parameter sets.\\
\textbf{Hardware tested.} Apple Silicon M2 Pro (12-core), macOS 15.4,
Go 1.26.3 darwin/arm64. Linux x86\_64 reference timings will land in
the v0.6 evaluation appendix.\\
\textbf{Dependencies.} \texttt{github.com/cloudflare/circl v1.6.3} (FIPS
205 SLH-DSA reference, BSD-3-Clause) and
\texttt{golang.org/x/crypto v0.32.0} (cSHAKE256 over FIPS 202 / NIST
SP 800-185). No private dependencies.\\
\textbf{Standards referenced.} FIPS 205 (SLH-DSA), FIPS 202 (SHA-3 /
SHAKE / cSHAKE), NIST SP 800-185 (KMAC / TupleHash / cSHAKE
customisation), NIST IR 8214C \cite{nistir8214c} (Multi-Party Threshold
Cryptography scope).\\
\textbf{Companion documents.} \texttt{SPEC.md} (normative construction),
\texttt{DEPLOYMENT-RUNBOOK.md} (public-BFT default + TEE-only
threshold paths), \texttt{BLOCKERS.md} (open gates), \texttt{CHANGELOG.md}
(release-by-release framing), \texttt{SUBMISSION.md} (NIST MPTC
