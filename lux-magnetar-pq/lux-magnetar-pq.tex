\begin{abstract}
We present \emph{Magnetar v0.1}, a threshold construction for FIPS 205
SLH-DSA \cite{fips205} that decomposes the SLH-DSA scheme seed across a
$(t,n)$ committee via byte-wise Shamir verifiable secret sharing over
$\mathrm{GF}(257)$, reconstructs the seed in aggregator memory during
signing, and invokes the single-party FIPS 205
$\textsc{SignDeterministic}$ on the reconstructed seed. The output is
\emph{byte-identical} to a centralized FIPS 205 signature on the same
$(\textsc{seed}, \mu, \mathit{ctx})$ triple --- Magnetar's
\emph{Class-N1-analog} claim, the hash-based counterpart of the Class N1
output-interchangeability property carried by Pulsar
v0.1 \cite{lp073pulsarpaper} and Corona R-LWE
v0.1 \cite{lp104corona}. Any unmodified FIPS 205 verifier accepts a
Magnetar signature without code change.

\textbf{Honest claim.} The v0.1 construction is straightforward and
faithful to the underlying primitives. What it is \emph{not} is a full
threshold MPC over the SLH-DSA hash tree: the aggregator process holds
the reconstructed master seed in memory for the duration of one
$\textsc{Combine}$ call. We make this caveat explicit and quantify the
$\sim 10\,\mathrm{ms}$ window during which the aggregator is in the
trusted computing base (TCB) of the deployment. Standard mitigations
(hardware-enclave aggregators, memory-encrypted VMs, ephemeral
aggregator processes with seccomp-bpf and forbidden-syscall whitelists)
neutralise the practical exposure; the paper documents both the residual
risk and the operational hardening.

The companion artefact is \texttt{luxfi/magnetar} v0.2.0
\cite{magnetargo} (Tier B at time of writing; commits \texttt{55a7c96}
through \texttt{db6c252}). The reference implementation totals
$\sim 3\,992$ lines of Go across 12 production source files, backed by
\texttt{cloudflare/circl/sign/slhdsa} v1.6.3 \cite{circl}. The
$\textsc{TestN1\_ByteEquality}$ empirical gate exercises the
byte-equality claim end-to-end across three thresholds; a passing run on
M2 Pro completes in $\sim 4.4$~s at $(3,2)$ and $\sim 20$~s at $(5,3)$
under the production CGO build.

Magnetar is positioned alongside Pulsar (M-LWE) and Corona (R-LWE) as
the \emph{hash-based} leg of the Lux Polaris cert profile, providing
cross-family cryptographic diversity against any single-family
algorithmic break. The path to Tier A is mechanically structured: the
v0.2 instantiation closes the aggregator-TCB caveat via a per-signature
MPC over the SLH-DSA hash tree; the path to that v0.2 is sketched in
\S\ref{sec:fullmpc} and \emph{nontrivial} --- SLH-DSA, unlike Schnorr or
ML-DSA, has no linear share-aggregation identity that would admit a
Komlo-style two-round threshold protocol.
\end{abstract}

\section*{Reproducibility}
\textbf{Source code.} \texttt{github.com/luxfi/magnetar} at tag
\texttt{v0.2.0} (Tier B graduation commit \texttt{89301f0}; deterministic
KAT generator commit \texttt{8ed01a3}; v0.1 reference implementation
commit \texttt{55a7c96}; submission-package mirror commits
\texttt{572147c} and \texttt{db6c252}).\\
\textbf{Build.} \texttt{cd ref/go \&\& GOWORK=off go build ./... \&\&
GOWORK=off go test -short ./pkg/magnetar/...}. The race-detector
($-$race) is supported but skips the SLH-DSA heavy paths via the
\texttt{raceEnabled} build-tag pattern; race-on runs cover the cheap
unit tests (shamir, transcript, types).\\
\textbf{Hardware tested.} Apple Silicon M2 Pro (12-core), macOS 15.4,
Go 1.26.3 darwin/arm64. Linux x86\_64 reference timings will land in
the v0.3 evaluation appendix.\\
\textbf{Dependencies.} \texttt{github.com/cloudflare/circl v1.6.3} (FIPS
205 SLH-DSA reference, BSD-3-Clause) and
\texttt{golang.org/x/crypto v0.32.0} (cSHAKE256 over FIPS 202 / NIST
SP 800-185). No private dependencies.\\
\textbf{Standards referenced.} FIPS 205 (SLH-DSA), FIPS 202 (SHA-3 /
SHAKE / cSHAKE), NIST SP 800-185 (KMAC / TupleHash / cSHAKE
customisation), NIST IR 8214C \cite{nistir8214c} (Multi-Party Threshold
Cryptography scope).\\

(NIST MPTC scaffold), \texttt{TRUSTED-COMPUTING-BASE.md} (TCB
