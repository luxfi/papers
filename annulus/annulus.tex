\begin{abstract}
\textbf{Quasar} is the Lux post-quantum cryptographic stack:
\PQ{} wallets, \PQ{} transaction authorization, \PQ{} contract
authorization, \PQ{} validator identity, \PQ{} DKG, \PQ{} finality,
\PQ{} rollup proofs, \PQ{} networking, and \PQ{} governance.
\textbf{\Annulus{}} is the strict-PQ \emph{boundary} of Quasar:
the ring that excludes classical crypto and enforces SHA3\_NIST,
ML-DSA, Pulsar finality, STARK / FRI proofs, ML-KEM networking,
and fail-closed verification.

\Annulus{} is not the whole stack and not a new primitive. It is
the visible boundary of the eclipse --- the ring of fire where
Quasar eclipses the legacy classical stack. Toolkits remain
configurable for forks and benchmarks; the Annulus boundary
itself is fail-closed.

This specification pins the boundary rules: the canonical
\texttt{ProfileID = QUASAR\_STRICT\_PQ} byte, the field-by-field
strict-PQ posture, the proof-envelope verifier gate, the
TxAuth / contract-auth / DKG / finality / networking subprofiles,
and the genesis-pinning discipline that makes operator flags
incapable of weakening the boundary at runtime.
\end{abstract}

\section{Profile, not primitive}
\label{sec:profile}
% =====================================================================

The architectural decision is the entire story:

\begin{quote}
\emph{Quasar is the PQ stack; \Annulus{} is its strict-PQ
boundary. Pulsar, Corona, P3Q, and the FIPS PQ primitives are
toolkits.}
\end{quote}

Forks can use BLAKE3, Keccak, Groth16, PLONK, ECDSA, BLS, fake
proofs, dev receipts, unsafe bridge wrappers. None of those are
\Annulus{}. \Annulus{} accepts only:

\begin{itemize}[leftmargin=*, itemsep=0pt]
\item ML-DSA-65 / 87 identities (FIPS~204).
\item ML-DSA-65 / 87 transaction and contract authorization, or
Z-Chain batched authorization proofs.
\item Pulsar-M threshold finality (M-LWE / FIPS~204-compatible).
\item ML-KEM-768 / 1024 networking channels (FIPS~203).
\item SHA3\_NIST hashes (cSHAKE, KMAC, TupleHash, ParallelHash;
FIPS~202 + SP~800-185).
\item STARK / FRI proof policy with transparent setup; no
pairings, no KZG, no Groth16/PLONK wrappers.
\item SLH-DSA cold-root / recovery (FIPS~205).
\end{itemize}

That single distinction --- toolkit vs profile --- is the entire
\Annulus{} architecture.

\section{Annulus-ID: identity and account layer}
\label{sec:annulus-id}
% =====================================================================

\Annulus{} accounts are not Ethereum-style 20-byte addresses. The
canonical account identity is:
\[
\textsf{AccountID} = \textsc{TupleHash256}\big(\textsc{``ANNULUS-ACCOUNT-ID-V1''},
\textit{profile\_id}, \textit{chain\_id}, \textit{scheme\_id},
\textit{pubkey}\big)[0{:}32].
\]
For high-value accounts, the SHAKE256-384 variant binds
$\textsc{``ANNULUS-HIGH-VALUE-ACCOUNT-V1''}$ and outputs 48 bytes.
Account records live on Z-Chain:

\begin{itemize}[leftmargin=*, itemsep=0pt]
\item \texttt{account\_id}
\item \texttt{scheme\_id} (ML-DSA-65 / 87 / SLH-DSA only)
\item \texttt{compact\_public\_key}, \texttt{expanded\_public\_key\_hash} (opt.)
\item \texttt{status} $\in \{$active, rotated, revoked, frozen$\}$
\item \texttt{valid\_from\_epoch}, \texttt{valid\_until\_epoch}
\item \texttt{rotation\_policy\_hash}, \texttt{recovery\_policy\_hash}
\end{itemize}

\textbf{Annulus accepts} only ML-DSA-65, ML-DSA-87, SLH-DSA keys.
\textbf{Annulus rejects} ECDSA, secp256k1-only, P-256-only WebAuthn,
and BLS account-auth keys.

\section{Annulus-TX: PQ transaction authorization}
\label{sec:annulus-tx}
% =====================================================================

Every transaction carries a self-describing auth envelope:

\begin{verbatim}
TxAuthEnvelope {
  version
  profile_id           = ANNULUS_STRICT_PQ
  chain_id, network_id
  account_id
  nonce
  expiry_height
  auth_scheme_id       = ML_DSA_65 | ZCHAIN_AUTH_PROOF
  hash_suite_id        = SHA3_NIST
  public_key_ref
  signature_or_proof_ref
  tx_digest
}
\end{verbatim}

\noindent
The digest is \textsc{TupleHash256}(\texttt{``ANNULUS-TX-AUTH-V1''},
profile\_id, chain\_id, network\_id, account\_id, nonce,
expiry\_height, fee\_payer, gas\_limit, max\_fee, call\_target,
call\_value, call\_data\_hash, zchain\_state\_root). Two paths
accepted: direct ML-DSA-65 signature, or a Z-Chain batched
authorization proof that lets wallets sign with ML-DSA while the
hot path stays small.

\section{Annulus-VM: PQ contracts}
\label{sec:annulus-vm}
% =====================================================================

Contracts must stop depending on \texttt{ecrecover}. \Annulus{} VM
host functions:

\begin{verbatim}
pq_verify_mldsa65(pk_ref_or_pk, digest, sig) -> bool
pq_verify_mldsa87(pk_ref_or_pk, digest, sig) -> bool
pq_verify_slh_dsa(pk_ref_or_pk, digest, sig) -> bool
pq_verify_z_auth_proof(account_id, digest, tx_auth_root, proof_ref) -> bool
pq_account_id_from_pubkey(scheme_id, pubkey) -> account_id
\end{verbatim}

\noindent
Contract auth profile defaults under \Annulus{}: \texttt{admin =
upgrade = ML-DSA-87 or SLH-DSA}; \texttt{pause = ML-DSA-65 multisig
or Pulsar committee}; \texttt{permit = ML-DSA-65 or
ZCHAIN\_AUTH\_PROOF}; \texttt{allow\_classical\_auth = false}.

The \texttt{PQPermit} envelope replaces ECDSA EIP-2612 permits and
carries
$\{\textit{profile\_id}, \textit{chain\_id},
\textit{verifying\_contract}, \textit{owner\_account\_id},
\textit{spender}, \textit{value}, \textit{nonce},
\textit{deadline}, \textit{auth\_scheme\_id},
\textit{hash\_suite\_id},
\textit{signature\_or\_zproof\_ref}\}$.

\section{Annulus-Z: PQ Z-Chain profile}
\label{sec:annulus-z}
% =====================================================================

Z-Chain is not a general EVM rollup in \Annulus{} core. It is a
\PQ{} authorization and state-proof rollup. It proves wallet key
registration, rotation, revocation, session-key authorization,
contract-policy updates, batched transaction-signature validity,
batched \PQ{} permits, validator identity validity, committee
selection, DKG transcript-root acceptance, group public-key
binding, and epoch commitment construction.

Public roots committed by Z-Chain:

\begin{itemize}[leftmargin=*, itemsep=0pt]
\item \texttt{identity\_root}, \texttt{account\_key\_root},
\texttt{revocation\_root}, \texttt{session\_key\_root}
\item \texttt{contract\_policy\_root}, \texttt{tx\_auth\_root},
\texttt{permit\_auth\_root}
\item \texttt{validator\_registry\_root}, \texttt{stake\_weight\_root},
\texttt{committee\_root}
\item \texttt{dkg\_transcript\_root}, \texttt{group\_public\_key\_hash}
\end{itemize}

\noindent
Proof policy: \texttt{ProofPolicyID = STARK\_FRI\_SHA3\_PQ}.
Allowed proof backends: SP1\_COMPRESSED\_STARK,
RISC0\_SUCCINCT\_STARK, P3Q\_PLONKY3\_STARK\_FRI,
STONE\_CAIRO\_STARK\_CPP, STWO\_CIRCLE\_STARK. STARK / FRI is the
right proof family for \Annulus{}: hash-based, transparent setup,
no pairings, no KZG, no trusted setup. SP1 and RISC0 are allowed
only along their STARK paths; their Groth16 / PLONK wrappers are
classical-SNARK fallbacks and \Annulus{} rejects them.

% =====================================================================
\section{P3Q: canonical long-term proof backend}
\label{sec:p3q}
% =====================================================================

P3Q is the Lux strict-PQ Plonky3 profile / fork. P3Q permits STARK,
FRI, Merkle / hash commitments, transparent setup, STARK-native
recursion, and external SHA3 / SHAKE / cSHAKE roots. P3Q forbids
BN254, KZG, Groth16, PLONK/KZG, pairings, elliptic-curve recursion,
and trusted setup. The distinction matters because Plonky3 is a
general polynomial-IOP toolkit; \Annulus{} pins a strict subset of
it rather than inheriting the whole toolkit unchecked.

Stone (Cairo CPU AIR, C++, Apache-2.0) and Stwo (Circle STARK,
Rust) are useful independent STARK backends and slot into the same
\texttt{ProofBackendID} surface alongside P3Q.

\section{Annulus-Q: Q-Chain finality profile}
\label{sec:annulus-q}
% =====================================================================

Q-Chain is the compact finality lane. Each Q-Block carries no raw
wallet keys, no raw validator keys, no raw transaction signatures,
no raw DKG messages, no full Z-Chain witness data, and no
classical fallback certs. Its transcript binds (no unbound field,
no silent fallback, no ``best effort''):

\begin{itemize}[leftmargin=*, itemsep=0pt]
\item \texttt{profile\_id}, \texttt{hash\_suite\_id},
\texttt{proof\_policy\_id}, \texttt{finality\_scheme\_id}
\item \texttt{network\_id}, \texttt{chain\_id}, \texttt{epoch},
\texttt{height}, \texttt{round\_or\_view},
\texttt{parent\_qblock\_hash}
\item \texttt{lux\_state\_root}, \texttt{zchain\_state\_root},
\texttt{tx\_auth\_root}, \texttt{payload\_root},
\texttt{da\_root}
\item \texttt{committee\_root}, \texttt{dkg\_transcript\_root},
\texttt{group\_public\_key\_hash}
\item \texttt{signer\_bitmap\_or\_weight\_commitment}
\end{itemize}

Each Q-Block carries a single Pulsar-65 threshold finality
certificate over the digest. High-value checkpoints use Pulsar-87.

\noindent
Flow: (1) Z-Chain proves validator registry and committee root;

accepts finality blocks only under the committed group key; (5)
each Q-Block carries a Pulsar-65 threshold finality certificate.

The NIST-facing statement stays narrow: \emph{Pulsar is a threshold
ML-DSA signing and DKG system targeting NIST MPTC Class N1 + N4,
with final signatures intended to verify under unmodified FIPS~204
ML-DSA verification}. That is much stronger and cleaner than
claiming the whole chain is FIPS-validated.

\section{Annulus-Gov: governance, bridge, upgrades}
\label{sec:annulus-gov}
% =====================================================================

Stronger / slower keys for rare high-value actions:

\begin{itemize}[leftmargin=*, itemsep=0pt]
\item Governance key: ML-DSA-87 or SLH-DSA.
\item Bridge admin key: ML-DSA-87 or SLH-DSA.
\item Upgrade key: SLH-DSA or ML-DSA-87 multisig.
\item Emergency pause: Pulsar committee or ML-DSA-87 multisig.
\item Checkpoint root: Pulsar-87.
\end{itemize}

\noindent
SLH-DSA (FIPS~205) is the right cold-root because it is stateless
and hash-based. A bridge is \Annulus{}-grade only if \emph{both
ends} are \PQ{}; otherwise the bridge must carry
\texttt{POST\_QUANTUM\_END\_TO\_END = false} and
\texttt{ANNULUS\_STRICT = false}.

\section{Proof envelope}
\label{sec:proof-envelope}
% =====================================================================

Every proof backend maps into one canonical envelope:

\begin{verbatim}
ZProofEnvelope {
  version
  profile_id, chain_id, network_id, epoch
  proof_policy_id, proof_backend_id, proof_format_id, verifier_id
  hash_suite_id, identity_scheme_id, finality_scheme_id
  public_inputs_hash, verifier_key_hash
  program_or_air_id, program_or_air_hash
  soundness_bits_claimed, hash_output_bits
  transparent_setup
  uses_pairings, uses_kzg, uses_trusted_setup,
  uses_classical_snark_wrapper
  proof_bytes
}
\end{verbatim}

\noindent
\Annulus{} verifier gate: refuse the envelope unless
\texttt{profile\_id == ANNULUS\_STRICT\_PQ},
\texttt{hash\_suite\_id == SHA3\_NIST},
\texttt{proof\_policy\_id == STARK\_FRI\_SHA3\_PQ},
\texttt{proof\_backend\_id} is in the allowed list,
\texttt{soundness\_bits\_claimed} $\geq 128$,
\texttt{hash\_output\_bits} $\geq 384$,
\texttt{transparent\_setup} is true,
\texttt{uses\_pairings = uses\_kzg = uses\_trusted\_setup =
uses\_classical\_snark\_wrapper = false}.

The backend cannot self-certify these flags. They are pinned by a
\texttt{VerifierManifest} signed by the chain governance:

\begin{verbatim}
VerifierManifest {
  verifier_id, backend_id, source_commit, build_profile
  verifier_key_hash, program_or_air_hash
  supports_policy_ids
  reviewed_soundness_bits
  uses_pairings, uses_kzg, uses_trusted_setup,
  uses_classical_snark_wrapper
}
\end{verbatim}

\section{Implementation order}
\label{sec:impl-order}
% =====================================================================

From the current state, the implementation order is:

\begin{enumerate}[leftmargin=*, itemsep=0pt]
\item \textbf{Close F22} --- Pulsar must use SHA3\_NIST HashSuite
internally by default.
\item \textbf{Close F34} --- Q-Chain digest must bind
\texttt{hash\_suite\_id}, \texttt{sig\_scheme\_id},
\texttt{proof\_policy\_id}, \texttt{committee\_root},
\texttt{dkg\_transcript\_root}, \texttt{group\_public\_key\_hash},
and \texttt{profile\_id}.
\item Add the \Annulus{} profile object; genesis-pinned,
hash-checked, zero-value-invalid.
\item Split proof IDs: \texttt{ProofPolicyID},
\texttt{ProofBackendID}, \texttt{ProofFormatID},
\texttt{VerifierID}.
\item Add \texttt{ZProofEnvelope}; one envelope for SP1, RISC0,
P3Q, Stone, Stwo.
\item Add \texttt{TxAuthEnvelope}; ML-DSA-65 direct and
\texttt{ZCHAIN\_AUTH\_PROOF} paths.
\item Add \PQ{} account registry; account keys, rotations,
revocations, sessions, contract policy.
\item Add \PQ{} VM host functions; ML-DSA / SLH-DSA verification,
Z-auth proof verification.
\item Disable classical auth in \Annulus{}; \texttt{ecrecover}
/ ECDSA / BLS / KZG / Groth16 rejected.
\item Add \Annulus{} status labels to RPC, explorer, metrics,
block headers.
\end{enumerate}
