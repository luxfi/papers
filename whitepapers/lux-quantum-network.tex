\section{Quantum Resistance of Existing Networks}

\subsubsection{Bitcoin}

Key Generation: Generates a private key and an ECDSA public key.


Address Creation:


The public key is hashed using SHA-256, then RIPEMD-160.


The result is the Bitcoin address.


Example process:
scss


SHA-256(Public Key) -> Hash1


RIPEMD-160(Hash1) -> Hash160


Bitcoin Address = Base58Check(VersionByte + Hash160 + Checksum)


Receiving Bitcoin: The address (not the public key) is shared publicly.


Spending Bitcoin:


When spending, the transaction reveals the public key to allow signature verification.


Public key exposure is minimized by using each address only once.


\subsubsection{Ethereum}

Key Generation: Generates a private key and an ECDSA public key.


Address Creation:


The Ethereum address is derived directly from the Keccak-256 hash of the public key.


The address is the last 20 bytes of this hash.


Example process:
mathematica


Keccak-256(Public Key) -> Hash


Ethereum Address = Last 20 bytes of Hash


Receiving Ether: The address, derived from the public key, is shared publicly.


Spending Ether:


Transactions are signed with the private key.


The public key can be derived from the signature, making it effectively always exposed.


\subsubsection{Solana}

Key Generation: Generates a private key and an ECDSA public key.


Address Creation: Uses the SHA-256 hash function and a different address format than Bitcoin and Ethereum.
plaintext


SHA-256(Public Key) -> Hash


Solana Address = Derived from Hash (specific format)


Receiving SOL: The address is shared publicly.


Spending SOL: Transactions reveal the public key similarly to Ethereum, with keys being derivable from signatures.


\subsubsection{Cardano}

Key Generation: Generates private and public keys for spending and staking.


Address Creation:
plaintext


PaymentKeyHash = Blake2b-224(PublicSpendingKey)


StakeKeyHash = Blake2b-224(PublicStakingKey)


BaseAddress = Bech32(NetworkID + PaymentKeyHash + StakeKeyHash)


Receiving ADA: The address (in Bech32 format) is shared publicly.


Spending ADA: Private spending key signs the transaction, revealing the public key.


\subsubsection{Key Differences}

Bitcoin:


Public key is hidden until you spend from an address.


Public key exposure is minimized by the recommended practice of using addresses only once.


Ethereum:


Public key is effectively always exposed because it can be derived from the transaction signature.


The address is a direct derivative of the public key.


\subsubsection{Quantum Resistance Implications}

Bitcoin:


More resistant due to the minimized exposure of the public key.


Attackers need to break the public key in the short time between transaction broadcast and block confirmation.


Ethereum:


Less resistant because the public key is always derivable from the address or transaction signature.


Easier target for quantum computing attacks if they become feasible.


Bitcoin's practice of only revealing the public key when spending adds an extra layer of protection compared to Ethereum, where the public key's continuous exposure could be a vulnerability in a future quantum computing scenario.

Key Processes

User Deposits BTC: User deposits BTC into the bridge, which goes into the MPC-managed multisig wallet.


Fresh Multisig Creation:


Create a new 3-of-5 multisig address using MPC.

2.⁠ ⁠Key Rotation


Continual Rotation:


Validators perform DKG to generate new keys each withdrawal.


No ECDSA public key is exposed for more than 10 minutes.


3.⁠ ⁠Withdrawal Event


Initiate Withdrawal:


Users initiate withdrawal requests.

Send the remaining 98 BTC to a newly generated multisig address.


Generate New Keys:


Use MPC to generate new keys for the new multisig address.


Transfer remaining funds to this new address, ensuring minimal exposure of ECDSA keys.
