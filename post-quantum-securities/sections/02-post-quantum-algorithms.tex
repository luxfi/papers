\subsection{ML-KEM (FIPS 203): Key Encapsulation}

\begin{definition}[Module-Lattice-Based Key Encapsulation]
ML-KEM provides IND-CCA2 secure key encapsulation based on the
Module Learning With Errors (MLWE) problem.  It replaces ECDH for
key agreement.

\begin{itemize}[nosep]
  \item \textbf{KeyGen} $\rightarrow (pk, sk)$: generates a lattice-based
        key pair.
  \item \textbf{Encapsulate}$(pk) \rightarrow (ct, ss)$: produces a
        ciphertext $ct$ and shared secret $ss$.
  \item \textbf{Decapsulate}$(sk, ct) \rightarrow ss$: recovers the
        shared secret.
\end{itemize}
\end{definition}

ML-KEM is used on the Lux network for:
\begin{itemize}[nosep]
  \item Encrypted peer-to-peer communication between validators.
  \item Key agreement for threshold FHE key distribution.
  \item Secure channel establishment for MPC signing sessions.
\end{itemize}

\subsection{ML-DSA (FIPS 204): Digital Signatures}

\begin{definition}[Module-Lattice-Based Digital Signature]
ML-DSA provides EUF-CMA secure digital signatures based on the MLWE
and Module-SIS problems.  It replaces ECDSA and Ed25519 for transaction
signing.

\begin{itemize}[nosep]
  \item \textbf{KeyGen} $\rightarrow (pk, sk)$: generates a lattice-based
        signing key pair.
  \item \textbf{Sign}$(sk, m) \rightarrow \sigma$: produces a signature
        on message $m$.
  \item \textbf{Verify}$(pk, m, \sigma) \rightarrow \{0, 1\}$: verifies
        the signature.
\end{itemize}
\end{definition}

ML-DSA is the primary post-quantum signature scheme for on-chain
operations: transaction signing, smart contract authorization, and
validator attestations.

\subsection{SLH-DSA (FIPS 205): Hash-Based Signatures}

\begin{definition}[Stateless Hash-Based Digital Signature]
SLH-DSA provides EUF-CMA secure digital signatures based solely on the
security of hash functions.  Unlike ML-DSA (which relies on lattice
assumptions), SLH-DSA's security rests on the one-wayness and
collision-resistance of SHA-256 / SHAKE-256.  It serves as a
conservative fallback: even if lattice assumptions are broken by
future advances, SLH-DSA remains secure as long as hash functions
are secure.
\end{definition}

SLH-DSA is used for:
\begin{itemize}[nosep]
  \item Root of trust signatures (genesis block, validator set changes).
  \item Long-term archival signatures on regulatory records.
  \item Fallback signing if ML-DSA is ever weakened.
\end{itemize}
