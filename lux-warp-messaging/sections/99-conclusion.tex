\section{Conclusion}
\label{sec:conclusion}

Lux Warp Messaging achieves trustless, efficient cross-appchain communication through five design choices:

\begin{enumerate}
    \item BLS aggregate signatures over BLS12-381 yield 48-byte constant-size proofs.
    \item A $2/3$ weighted-stake quorum inherits trust from appchain consensus with no external assumptions.
    \item Domain-separated hash-to-curve and nonce-based replay protection ensure message integrity.
    \item Optimistic delivery with economic bonds and fraud proofs reduces latency to sub-second for time-sensitive applications.
    \item Native EVM precompiles reduce on-chain verification to 50,000 gas, enabling practical cross-chain composability.
\end{enumerate}

\subsection{Message Acknowledgment}

For reliable delivery with confirmation, LWM supports acknowledgment messages:

\begin{definition}[Acknowledged Message]
An acknowledged warp message triggers a return message from the destination to the source confirming execution:
\begin{equation}
    \mathcal{M}_{\text{ack}} = (\mathsf{dst}, \mathsf{src}, \mathsf{ack\_nonce}, H(\mathsf{result}), \infty, 0)
\end{equation}
The source contract can wait for $\mathcal{M}_{\text{ack}}$ to confirm successful execution before finalizing state transitions.
\end{definition}

This enables two-phase commit protocols for atomic cross-appchain operations.

\subsection{Replay Protection}

Every Warp message includes a monotonically increasing nonce per source appchain and a chain identifier, preventing replay attacks across appchains or after chain reorganizations:

\begin{definition}[Replay-Safe Message]
A message $m$ is replay-safe if and only if:
\begin{enumerate}
    \item $m.\texttt{nonce} > \texttt{lastSeen}[\texttt{sourceAppchain}]$ at the destination.
    \item $m.\texttt{chainID}$ matches the destination's expected source chain identifier.
    \item $m.\texttt{expiry} > \texttt{currentTimestamp}$ (message has not expired).
\end{enumerate}
The destination chain maintains a per-source-appchain nonce watermark. Out-of-order delivery is permitted: the watermark advances to $\max(\texttt{lastSeen}, m.\texttt{nonce})$, and a bitmap tracks received nonces within a sliding window of size $W = 256$ to reject duplicates without requiring strict ordering.
\end{definition}

\begin{algorithm}
\caption{Nonce Verification with Bitmap}
\begin{algorithmic}[1]
\Require Message $m$, watermark $w$, bitmap $B[0..255]$
\If{$m.\texttt{nonce} \leq w - 256$}
    \State \Return \textbf{reject} (too old)
\EndIf
\If{$m.\texttt{nonce} \leq w$}
    \If{$B[m.\texttt{nonce} \bmod 256] = 1$}
        \State \Return \textbf{reject} (duplicate)
    \EndIf
    \State $B[m.\texttt{nonce} \bmod 256] \gets 1$
\Else
    \State Clear bits in $B$ for nonces in $(w, m.\texttt{nonce} - 256]$
    \State $w \gets m.\texttt{nonce}$
    \State $B[m.\texttt{nonce} \bmod 256] \gets 1$
\EndIf
\State \Return \textbf{accept}
\end{algorithmic}
\end{algorithm}

\subsection{Congestion Feedback}

The protocol includes a congestion signaling mechanism. Each destination appchain maintains a message ingestion rate counter $\lambda_{\text{in}}$ (messages per second). When $\lambda_{\text{in}}$ exceeds the processing capacity $\lambda_{\max}$, the destination emits a backpressure signal via Warp to the source appchain:

\begin{equation}
    \texttt{backpressure}(t) = \max\!\left(0, \frac{\lambda_{\text{in}}(t) - \lambda_{\max}}{\lambda_{\max}}\right)
\end{equation}

Source appchains receiving a non-zero backpressure signal apply exponential backoff to their outbound message rate, reducing transmission by a factor of $2^{-k}$ after $k$ consecutive congestion signals. Normal transmission resumes after receiving a zero-backpressure acknowledgment.

The protocol is live on Lux Network mainnet and supports the growing appchain ecosystem. Future work includes recursive BLS aggregation for multi-hop routing, threshold signature schemes for enhanced privacy, and integration with zero-knowledge proofs for compressed state assertions.
