\section{Cooldown for deprecated allocations}
\label{sec:cooldown}

When an allocation is marked Deprecated, the slot is NOT immediately
reusable. A one-year cooldown applies before re-allocation, to give
node operators and indexers time to drop the old code paths.

\subsection{Why a cooldown}

Three concrete failure modes if a deprecated slot is re-allocated
without cooldown:

\begin{enumerate}[leftmargin=2em,nosep]
\item \textbf{Stale node software.} Validator binaries pinned to the
  pre-deprecation release continue to dispatch the old precompile.
  A re-allocation makes that dispatch return semantically-different
  data; the validator's view of the chain forks silently from the
  network.
\item \textbf{Indexer leaks.} Off-chain indexers that scrape
  historical data may not pick up the new allocation immediately.
  Returning historical traces conflates the old and new semantics
  on the same slot.
\item \textbf{Audit confusion.} Forensic analysis of a contract that
  called the deprecated slot becomes ambiguous: was the dispatch
  pre- or post-re-allocation? Without a cooldown window, the line is
  blurred.
\end{enumerate}

The cooldown removes all three failure modes by guaranteeing a
calendar window in which the slot is dead -- no dispatch is valid,
no allocation is honored.

\subsection{Cooldown procedure}

\begin{enumerate}[leftmargin=2em,nosep]
\item An LP-300 amendment moves the row from its active table to the
  Deprecated table (\S\ref{sec:precomp-deprecated} for precompiles;
  analogous tables for TypeKind / ShapeKind).
\item The amendment records both the \texttt{Deprecated} date and
  the \texttt{Re-allocatable} date (Deprecated + 365 days).
\item The consuming LP that owned the deprecated slot is amended in
  the same PR cycle to mark the deprecation and cite the LP-300 row.
\item During the cooldown, no LP MAY re-allocate the slot. A PR that
  attempts to do so is rejected by the LP-300 maintainer until the
  re-allocatable date has passed.
\item On or after the re-allocatable date, the slot becomes
  candidate for re-allocation per the standard amendment-first rule
  (\S\ref{sec:policy}). The LP-300 row stays in the Deprecated table
  until a new amendment moves it elsewhere.
\end{enumerate}

\subsection{Activation marker}

LP-300 itself is \textbf{Final} from genesis -- unix
\texttt{1766708400} = 2025-12-25T16:20:00-08:00 -- because it is a
meta-registry, not a wire change. The first time the consuming LPs
(LP-208, LP-211, LP-214, LP-218, LP-219, LP-220) cross activation in
production, LP-300 is the binding map. Any disagreement between this
LP and a consuming LP is resolved in favor of LP-300; the consuming
LP must be amended in a follow-up PR.

The activation marker is also the reference time-zero for cooldown
arithmetic. A deprecation on 2026-05-18 (pre-activation) carries
forward post-activation as a calendar window, not a height window;
the cooldown is measured in days from the deprecation date, not
blocks from activation.
