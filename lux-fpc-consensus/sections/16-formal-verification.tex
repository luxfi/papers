\subsection{Key Theorems}

\begin{theorem}[Machine-Checked Safety]
\label{thm:formal-safety}
For any two honest nodes $i$, $j$ that finalize values $v_1$, $v_2$ at the same height:
$$\forall\, i, j, v_1, v_2.\; \mathsf{honest}(i) \land \mathsf{honest}(j) \land \mathsf{finalized}(i, v_1) \land \mathsf{finalized}(j, v_2) \implies v_1 = v_2$$
Proved in \texttt{Consensus.Safety.safety} via unique-threshold lemma and confidence monotonicity.
\end{theorem}

\begin{theorem}[Machine-Checked Finalization]
\label{thm:formal-finalization}
After $\beta$ consecutive rounds where the yes-vote count meets the $\alpha$ threshold and matches the current preference, the item is decided:
$$\mathsf{confidence}(s) + 1 \geq \beta \implies \mathsf{step}(\mathit{cfg}, s, r).\mathsf{decided} = \mathsf{true}$$
Proved in \texttt{Protocol.Wave.finalization\_after\_beta} by unfolding the step function.
\end{theorem}

\begin{theorem}[Machine-Checked Decision Stability]
\label{thm:formal-stability}
Once a Wave item is decided, no further round changes its state:
$$\mathsf{decided}(s) = \mathsf{true} \implies \mathsf{step}(\mathit{cfg}, s, r) = s$$
Proved in \texttt{Protocol.Wave.decided\_is\_stable} by the early-return guard in the step function.
\end{theorem}

\subsection{Verification Methodology}

Each Lean theorem maps to a specific code path in the Go implementation via comments that reference exact file paths and line numbers (e.g., \texttt{wave.go:98-102} for the early-return guard). This traceability ensures that the formal model accurately reflects the deployed code. The Lean proofs are type-checked by the Lean~4 compiler and verified in CI on every commit to the \texttt{luxfi/formal} repository.
