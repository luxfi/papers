\begin{abstract}
We present the Platform Virtual Machine (Platform VM), the core governance layer for the Lux blockchain network. The Platform VM implements stake-weighted validator sampling, dynamic subnet management, and delegation protocols that enable a heterogeneous multi-chain architecture. Our design achieves linear-time validator set updates, supports permissioned and permissionless subnet configurations, and provides cryptographic guarantees for staking operations. We analyze the security properties of stake-weighted sampling and demonstrate that the Platform VM maintains Byzantine fault tolerance under adversarial conditions. Experimental evaluation shows sub-second validator set lookups at scale and efficient reward distribution across thousands of validators.
\end{abstract}

\section{Introduction}

Modern blockchain systems require flexible governance mechanisms that can adapt to diverse application requirements while maintaining security guarantees. The Platform VM serves as the meta-layer for the Lux network, managing validators, subnets, and staking operations across all chains in the ecosystem.

Unlike single-chain systems where validator management is tightly coupled with consensus, the Platform VM decouples these concerns. This separation enables:
\begin{itemize}
    \item Independent chains with custom consensus parameters
    \item Dynamic validator set changes without chain restarts
    \item Flexible delegation and reward mechanisms
    \item Permissioned subnets for enterprise deployments
\end{itemize}

The primary contributions of this paper are:
\begin{enumerate}
    \item A formal model for stake-weighted validator sampling with proven security bounds
    \item Efficient data structures for validator set management supporting $O(1)$ lookups
    \item A delegation protocol with configurable reward sharing
    \item Subnet permission models supporting both open and permissioned configurations
\end{enumerate}

\section{System Model}

\subsection{Network Structure}

The Lux network consists of a Primary Network and zero or more subnets. Each subnet operates its own set of blockchains with independent consensus parameters.

\begin{definition}[Subnet]
A subnet $S = (V_S, C_S, \Pi_S)$ is defined by:
\begin{itemize}
    \item $V_S \subseteq V$: Validator set (subset of all validators)
    \item $C_S$: Set of chains operated by the subnet
    \item $\Pi_S$: Permission policy for validator admission
\end{itemize}
\end{definition}

The Primary Network is a distinguished subnet that all validators must participate in. This ensures a common trust anchor for cross-subnet communication.

\subsection{Staking Model}

Validators participate by staking tokens for a bounded duration. The staking model is defined as follows:

\begin{definition}[Staker]
A staker $s = (id, w, t_s, t_e, pk)$ consists of:
\begin{itemize}
    \item $id$: Unique node identifier (NodeID)
    \item $w$: Stake weight (in native tokens)
    \item $t_s, t_e$: Start and end timestamps
    \item $pk$: BLS public key for aggregate signatures
\end{itemize}
\end{definition}

\section{Validator Set Management}

\subsection{Stake-Weighted Sampling}

The Platform VM uses stake-weighted sampling to select block proposers and committee members. The sampling algorithm ensures that validators are selected proportionally to their stake.

\begin{algorithm}
\caption{Stake-Weighted Validator Sampling}
\label{alg:sampling}
\begin{algorithmic}[1]
\Require Validator set $V$, seed $\sigma$, count $k$
\Ensure Selected validators $S$ of size $k$
\State $W \gets \sum_{v \in V} v.weight$
\State $S \gets \emptyset$
\State $rng \gets \text{InitPRNG}(\sigma)$
\For{$i = 1$ to $k$}
    \State $r \gets rng.\text{Uniform}(0, W)$
    \State $cumulative \gets 0$
    \For{$v \in V$}
        \State $cumulative \gets cumulative + v.weight$
        \If{$cumulative > r$}
            \State $S \gets S \cup \{v\}$
            \State \textbf{break}
        \EndIf
    \EndFor
\EndFor
\State \Return $S$
\end{algorithmic}
\end{algorithm}

For efficient repeated sampling, we maintain a cumulative weight tree:

\begin{definition}[Weight Tree]
A weight tree $T$ over validators $V$ is a binary tree where:
\begin{itemize}
    \item Leaves store individual validator weights
    \item Internal nodes store subtree weight sums
    \item Root stores total weight $W = \sum_{v \in V} w_v$
\end{itemize}
\end{definition}

This structure enables $O(\log n)$ sampling and $O(\log n)$ weight updates.

\section{Staking Protocol}

\subsection{Validator Registration}

To become a validator, a node submits an \texttt{AddValidatorTx} transaction:

\begin{algorithm}
\caption{Validator Registration}
\label{alg:registration}
\begin{algorithmic}[1]
\Require Transaction $tx$, current state $S$
\Ensure Updated state $S'$ or error
\State Verify $tx.stake \geq \text{MinValidatorStake}$
\State Verify $tx.duration \geq \text{MinStakeDuration}$
\State Verify $tx.duration \leq \text{MaxStakeDuration}$
\State Verify $tx.nodeID \notin S.\text{validators}$
\State Verify BLS proof of possession for $tx.publicKey$
\State $staker \gets \text{NewStaker}(tx)$
\State $S'.\text{pendingValidators}.\text{Add}(staker)$
\State \Return $S'$
\end{algorithmic}
\end{algorithm}

\subsection{Delegation}

Delegators can stake tokens to existing validators without running a node:

\begin{definition}[Delegation]
A delegation $d = (delegator, validator, w, t_s, t_e, share)$ where:
\begin{itemize}
    \item $delegator$: Address of the delegating party
    \item $validator$: Target validator's NodeID
    \item $w$: Delegated stake weight
    \item $share$: Validator's reward share (percentage)
\end{itemize}
\end{definition}

The total weight for a validator $v$ with delegations $D_v$ is:
\begin{equation}
W_v = w_v + \sum_{d \in D_v} w_d
\end{equation}

\subsection{Reward Calculation}

Rewards are calculated based on staking duration and network supply:

\begin{equation}
R = \frac{(S_{cap} - S_{current}) \cdot w \cdot t \cdot r}{S_{current} \cdot T_{period}}
\end{equation}

where:
\begin{itemize}
    \item $S_{cap}$: Maximum token supply
    \item $S_{current}$: Current circulating supply
    \item $w$: Staked amount
    \item $t$: Staking duration
    \item $r$: Consumption rate (min to max based on duration)
    \item $T_{period}$: Minting period
\end{itemize}

\begin{lstlisting}[language=Go, caption=Reward Calculator]
func (c *calculator) Calculate(
    stakedDuration time.Duration,
    stakedAmount, currentSupply uint64,
) uint64 {
    // RemainingSupply = SupplyCap - ExistingSupply
    // MintingRate = Min + (Max-Min) * Duration/MaxDuration
    // Reward = Remaining * Amount/Supply * Rate * Duration
    remainingSupply := c.supplyCap - currentSupply
    reward := new(big.Int).SetUint64(remainingSupply)
    reward.Mul(reward, adjustedRate)
    reward.Mul(reward, stakedAmount)
    reward.Div(reward, currentSupply)
    reward.Div(reward, mintingPeriod)
    return min(remainingSupply, reward.Uint64())
}
\end{lstlisting}

\section{Security Analysis}

\subsection{Stake-Weighted Sampling Security}

\begin{theorem}[Sampling Security]
For a stake-weighted sample of size $k$ from validators with total honest stake fraction $h > 2/3$, the probability that less than $2/3$ of the sample is honest is bounded by:
\begin{equation}
P[\text{sample unsafe}] \leq e^{-2k(h - 2/3)^2}
\end{equation}
\end{theorem}

\begin{proof}
By Hoeffding's inequality applied to Bernoulli sampling with replacement probability $h$.
\end{proof}

\subsection{Sybil Resistance}

The minimum stake requirement provides economic Sybil resistance:

\begin{property}[Sybil Cost]
Creating $n$ validator identities requires staking $n \cdot \text{MinStake}$ tokens, making Sybil attacks economically prohibitive.
\end{property}

\subsection{Long-Range Attack Prevention}

Validator sets are indexed by P-chain height, enabling verification that:
\begin{enumerate}
    \item Blocks are signed by validators active at the claimed height
    \item Validator weights match the historical state
    \item BLS signatures aggregate correctly
\end{enumerate}

\subsection{Caching Strategy}

Validator sets are cached with LRU eviction:

\begin{itemize}
    \item Cache size: 64 entries per subnet
    \item Cache key: (subnetID, height)
    \item Cache miss: Reconstruct from current state via diffs
\end{itemize}

\subsection{Metrics}

The Platform VM exposes detailed metrics:

\begin{itemize}
    \item \texttt{validator\_sets\_cached}: Cache hit count
    \item \texttt{validator\_sets\_created}: Cache miss count
    \item \texttt{validator\_sets\_duration}: Reconstruction time
    \item \texttt{validator\_sets\_height\_diff}: Height delta for reconstruction
\end{itemize}
