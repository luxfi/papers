\section{Teleport Protocol: End-to-End Flow}


The Teleport protocol implements four operations using the authenticated message protocol.

\subsection{Deposit}

\begin{enumerate}[leftmargin=2em]
\item User calls \texttt{TeleportVault.deposit(asset, amount, dstChain, recipient)} on source chain.
\item Vault locks \texttt{amount} of \texttt{asset} and emits a \texttt{Deposited} event.
\item MPC watchers observe the event and wait for source chain finality.
\end{enumerate}

\subsection{Burn (MPC Internal)}

\begin{enumerate}[leftmargin=2em]
\item After finality confirmation, MPC nodes construct a \texttt{BURN} message.
\item $t$-of-$n$ nodes sign the message hash.
\item The signed \texttt{BURN} message is recorded in the MPC event log.
\end{enumerate}

\subsection{Release}

\begin{enumerate}[leftmargin=2em]
\item The relayer submits the signed \texttt{RELEASE} message to the destination chain.
\item The destination chain's \texttt{TeleportRouter} runs all 8 verification checks.
\item If verified, the router mints wrapped tokens (or releases native tokens) to \texttt{recipient}.
\end{enumerate}

\subsection{Backing Attestation}

\begin{enumerate}[leftmargin=2em]
\item Periodically, the MPC committee attests to the total backing per asset per chain.
\item The \texttt{BACKING} message contains a monotonically increasing backing amount.
\item Destination chains compare minted supply against attested backing.
\item If $\text{minted} > \text{backing} \times (1 + \epsilon)$, the bridge auto-pauses.
\end{enumerate}

\begin{invariant}[Backing Monotonicity]
For any asset $a$ and chain $c$, backing attestation amounts are monotonically non-decreasing: $\text{backing}(a, c, t_1) \leq \text{backing}(a, c, t_2)$ for $t_1 < t_2$.
\end{invariant}
