\begin{abstract}
We present the Lux Go SDK, the first official client library for the Lux blockchain platform. Written in Go to match the core node implementation, this SDK provides native performance for transaction building, cryptographic signing, and multi-chain interaction. We detail the architecture decisions that enable type-safe API access, efficient serialization, and seamless integration with the Snow consensus family. Benchmarks demonstrate sub-millisecond transaction construction and signing operations, making the SDK suitable for high-frequency trading applications and validator tooling. The SDK serves as the reference implementation for subsequent language bindings.
\end{abstract}

\section{Introduction}

The Lux blockchain platform introduces a novel multi-chain architecture with heterogeneous consensus mechanisms. The Primary Network consists of three built-in chains: the Exchange Chain (X-Chain) for asset creation and trading using Avalanche consensus, the Platform Chain (P-Chain) for validator coordination using Snowman consensus, and the Contract Chain (C-Chain) for smart contract execution using a modified Snowman variant.

Developers building on Lux require programmatic access to all three chains with consistent APIs, strong type safety, and performance characteristics suitable for production applications. The Go programming language provides an ideal foundation: static typing prevents runtime errors, goroutines enable concurrent operations, and the garbage collector manages memory without compromising latency.

This paper presents the Lux Go SDK, designed with the following principles:

\begin{itemize}
    \item \textbf{Zero-copy where possible}: Minimize allocations in hot paths
    \item \textbf{Explicit error handling}: All operations return errors
    \item \textbf{Composable primitives}: Small interfaces, orthogonal functions
    \item \textbf{Standard library first}: Minimal external dependencies
\end{itemize}

The SDK follows a layered architecture separating concerns into distinct packages:

    platformvm/  // P-Chain operations
    evm/     // C-Chain operations

\subsection{Identifier Types}

Lux uses 32-byte identifiers extensively. Rather than passing raw byte slices, the SDK defines typed identifiers:

\begin{lstlisting}[language=Go,caption=Typed Identifiers]
package ids

// ID represents a 32-byte identifier
type ID [32]byte

// ShortID represents a 20-byte address
type ShortID [20]byte

// NodeID identifies a validator node
type NodeID ShortID

// Methods for string conversion, comparison
func (id ID) String() string {
    return base58.Encode(id[:])
}

func (id ID) MarshalJSON() ([]byte, error) {
    return json.Marshal(id.String())
}
\end{lstlisting}

Type safety prevents mixing identifiers: a transaction ID cannot be accidentally used where a chain ID is expected. The compiler catches these errors at build time.

\subsection{Codec System}

Lux uses a custom binary serialization format optimized for compactness and determinism. The codec package provides registration-based type handling:

\begin{lstlisting}[language=Go,caption=Codec Registration]
package codec

type Manager interface {
    RegisterCodec(version uint16, codec Codec) error
    Marshal(version uint16, v interface{}) ([]byte, error)
    Unmarshal(bytes []byte, v interface{}) (uint16, error)
}

// Registration at init time
func init() {
    c := linearcodec.NewDefault()
    c.RegisterType(&BaseTx{})
    c.RegisterType(&CreateAssetTx{})
    c.RegisterType(&OperationTx{})
    manager.RegisterCodec(0, c)
}
\end{lstlisting}

Deterministic marshaling ensures that identical transactions produce identical bytes, critical for signature verification and transaction deduplication.

\section{Cryptographic Primitives}

\subsection{Key Management}

The SDK supports secp256k1 ECDSA, the same curve used by Bitcoin and Ethereum:

\begin{lstlisting}[language=Go,caption=Key Operations]
package crypto

type PrivateKey interface {
    PublicKey() PublicKey
    Sign(msg []byte) ([]byte, error)
    Bytes() []byte
}

type Factory interface {
    NewPrivateKey() (PrivateKey, error)
    ToPrivateKey([]byte) (PrivateKey, error)
}

// SECP256K1 implementation
type secp256k1Factory struct{}

func (f *secp256k1Factory) NewPrivateKey() (PrivateKey, error) {
    key, err := ecdsa.GenerateKey(secp256k1.S256(), rand.Reader)
    if err != nil {
        return nil, err
    }
    return &secp256k1PrivateKey{privateKey: key}, nil
}
\end{lstlisting}

\subsection{Address Derivation}

Addresses derive from public keys through hashing:

\begin{lstlisting}[language=Go,caption=Address Derivation]
func (pk *secp256k1PublicKey) Address() ids.ShortID {
    // SHA256 then RIPEMD160
    sha := sha256.Sum256(pk.Bytes())
    ripemd := ripemd160.New()
    ripemd.Write(sha[:])

    var addr ids.ShortID
    copy(addr[:], ripemd.Sum(nil))
    return addr
}
\end{lstlisting}

\subsection{Bech32 Encoding}

Human-readable addresses use Bech32 encoding with chain-specific prefixes:

\begin{lstlisting}[language=Go,caption=Bech32 Addresses]
// X-lux1qpm2fs7a9tke9rp7ck7kdcem4xlz5uy30vgjv2
func FormatAddress(
    chainAlias string,
    hrp string,
    addr ids.ShortID,
) (string, error) {
    addrStr, err := bech32.Encode(hrp, addr[:])
    if err != nil {
        return "", err
    }
    return fmt.Sprintf("%s-%s", chainAlias, addrStr), nil
}
\end{lstlisting}

\section{Transaction Building}

\subsection{UTXO Model (X-Chain)}

The X-Chain uses an unspent transaction output model. Building a transaction requires:

\begin{enumerate}
    \item Fetching UTXOs for source addresses
    \item Selecting inputs to cover outputs plus fees
    \item Constructing and signing the transaction
\end{enumerate}

\begin{lstlisting}[language=Go,caption=X-Chain Transaction]
func (w *Wallet) SendX(
    ctx context.Context,
    to ids.ShortID,
    amount uint64,
    assetID ids.ID,
) (ids.ID, error) {
    // Fetch spendable UTXOs
    utxos, err := w.xClient.GetUTXOs(ctx, w.Addresses())
    if err != nil {
        return ids.Empty, err
    }

    // Build transaction
    builder := txs.NewBuilder(w.networkID, w.xChainID)

    unsignedTx, err := builder.NewBaseTx(
        utxos,
        []*lux.TransferableOutput{{
            Asset: lux.Asset{ID: assetID},
            Out: &secp256k1fx.TransferOutput{
                Amt: amount,
                OutputOwners: secp256k1fx.OutputOwners{
                    Threshold: 1,
                    Addrs:     []ids.ShortID{to},
                },
            },
        }},
        w.changeAddr,
    )
    if err != nil {
        return ids.Empty, err
    }

    // Sign with keychain
    tx, err := w.keychain.Sign(unsignedTx)
    if err != nil {
        return ids.Empty, err
    }

    // Submit
    return w.xClient.IssueTx(ctx, tx.Bytes())
}
\end{lstlisting}

\subsection{Account Model (C-Chain)}

The C-Chain uses Ethereum's account model. The SDK wraps go-ethereum types:

\begin{lstlisting}[language=Go,caption=C-Chain Transaction]
func (w *Wallet) SendC(
    ctx context.Context,
    to common.Address,
    amount *big.Int,
) (common.Hash, error) {
    // Get nonce
    nonce, err := w.cClient.NonceAt(ctx, w.ethAddr, nil)
    if err != nil {
        return common.Hash{}, err
    }

    // Estimate gas
    gasPrice, err := w.cClient.SuggestGasPrice(ctx)
    if err != nil {
        return common.Hash{}, err
    }

    // Build transaction
    tx := types.NewTransaction(
        nonce,
        to,
        amount,
        21000,  // standard transfer gas
        gasPrice,
        nil,
    )

    // Sign
    signedTx, err := types.SignTx(
        tx,
        types.NewEIP155Signer(w.chainID),
        w.ethKey,
    )
    if err != nil {
        return common.Hash{}, err
    }

    // Submit
    return signedTx.Hash(), w.cClient.SendTransaction(ctx, signedTx)
}
\end{lstlisting}

\subsection{Staking Operations (P-Chain)}

Validator registration requires bonded stake:

\begin{lstlisting}[language=Go,caption=Add Validator Transaction]
func (w *Wallet) AddValidator(
    ctx context.Context,
    nodeID ids.NodeID,
    stake uint64,
    startTime, endTime time.Time,
    rewardAddr ids.ShortID,
    delegationFee uint32,
) (ids.ID, error) {
    utxos, err := w.pClient.GetUTXOs(ctx, w.Addresses())
    if err != nil {
        return ids.Empty, err
    }

    builder := txs.NewBuilder(w.networkID, w.pChainID)

    unsignedTx, err := builder.NewAddValidatorTx(
        utxos,
        &validator.Validator{
            NodeID: nodeID,
            Start:  uint64(startTime.Unix()),
            End:    uint64(endTime.Unix()),
            Wght:   stake,
        },
        rewardAddr,
        delegationFee,
        w.changeAddr,
    )
    if err != nil {
        return ids.Empty, err
    }

    tx, err := w.keychain.Sign(unsignedTx)
    if err != nil {
        return ids.Empty, err
    }

    return w.pClient.IssueTx(ctx, tx.Bytes())
}
\end{lstlisting}

\subsection{Retry Logic}

Transient failures trigger retries with exponential backoff:

\begin{lstlisting}[language=Go,caption=Retry Wrapper]
func (c *Client) callWithRetry(
    ctx context.Context,
    method string,
    params interface{},
) (json.RawMessage, error) {
    var lastErr error
    for attempt := 0; attempt < 3; attempt++ {
        resp, err := c.call(ctx, method, params)
        if err == nil {
            return resp, nil
        }

        if !isRetryable(err) {
            return nil, err
        }

        lastErr = err
        select {
        case <-ctx.Done():
            return nil, ctx.Err()
        case <-time.After(backoff(attempt)):
        }
    }
    return nil, lastErr
}
\end{lstlisting}

\section{Wallet Implementation}

\subsection{HD Derivation}

The wallet supports BIP-32/BIP-44 hierarchical deterministic key derivation:

\begin{lstlisting}[language=Go,caption=HD Key Derivation]
// BIP-44 path: m/44'/9000'/0'/0/index
const (
    Purpose   = 44
    CoinType  = 9000  // Lux coin type
    Account   = 0
    Change    = 0
)

func (w *HDWallet) DeriveKey(index uint32) (PrivateKey, error) {
    path := []uint32{
        Purpose + HardenedOffset,
        CoinType + HardenedOffset,
        Account + HardenedOffset,
        Change,
        index,
    }

    key := w.masterKey
    for _, i := range path {
        var err error
        key, err = key.Derive(i)
        if err != nil {
            return nil, err
        }
    }

    return keyFromExtended(key)
}
\end{lstlisting}

\subsection{Keychain Interface}

The keychain manages multiple keys and selects signers:

\begin{lstlisting}[language=Go,caption=Keychain Interface]
type Keychain interface {
    Addresses() []ids.ShortID
    Get(addr ids.ShortID) (PrivateKey, bool)
    Sign(tx UnsignedTx) (*Tx, error)
}

func (k *keychain) Sign(utx UnsignedTx) (*Tx, error) {
    // Get required signers from transaction inputs
    signers := utx.InputSigners()

    creds := make([]verify.Verifiable, len(signers))
    for i, signerAddrs := range signers {
        sigs := make([][]byte, len(signerAddrs))
        for j, addr := range signerAddrs {
            key, ok := k.Get(addr)
            if !ok {
                return nil, fmt.Errorf("missing key for %s", addr)
            }

            sig, err := key.Sign(utx.Bytes())
            if err != nil {
                return nil, err
            }
            sigs[j] = sig
        }
        creds[i] = &secp256k1fx.Credential{Sigs: sigs}
    }

    return &Tx{
        Unsigned: utx,
        Creds:    creds,
    }, nil
}
\end{lstlisting}

\section{Concurrency Patterns}

\subsection{Parallel UTXO Fetching}

Fetching UTXOs from multiple addresses benefits from concurrency:

\begin{lstlisting}[language=Go,caption=Concurrent UTXO Fetch]
func (c *Client) GetUTXOsMulti(
    ctx context.Context,
    addrs []ids.ShortID,
) ([]*lux.UTXO, error) {
    // Batch addresses to avoid overwhelming the node
    batches := batch(addrs, 100)

    var wg sync.WaitGroup
    results := make(chan []*lux.UTXO, len(batches))
    errs := make(chan error, len(batches))

    for _, batch := range batches {
        wg.Add(1)
        go func(addrs []ids.ShortID) {
            defer wg.Done()
            utxos, err := c.GetUTXOs(ctx, addrs)
            if err != nil {
                errs <- err
                return
            }
            results <- utxos
        }(batch)
    }

    wg.Wait()
    close(results)
    close(errs)

    // Check for errors
    if err := <-errs; err != nil {
        return nil, err
    }

    // Collect results
    var all []*lux.UTXO
    for utxos := range results {
        all = append(all, utxos...)
    }
    return all, nil
}
\end{lstlisting}

\subsection{Transaction Confirmation}

Waiting for transaction confirmation uses polling with context cancellation:

\begin{lstlisting}[language=Go,caption=Confirmation Polling]
func (c *Client) WaitForAccepted(
    ctx context.Context,
    txID ids.ID,
) error {
    ticker := time.NewTicker(500 * time.Millisecond)
    defer ticker.Stop()

    for {
        select {
        case <-ctx.Done():
            return ctx.Err()
        case <-ticker.C:
            status, err := c.GetTxStatus(ctx, txID)
            if err != nil {
                return err
            }
            switch status {
            case StatusAccepted:
                return nil
            case StatusRejected:
                return ErrTxRejected
            case StatusProcessing, StatusUnknown:
                continue
            }
        }
    }
}
\end{lstlisting}

\section{Usage Example}

A complete example demonstrating SDK usage:

\begin{lstlisting}[language=Go,caption=Complete Example]
package main

import (
    "context"
    "log"

    "github.com/luxfi/sdk-go/wallet"
    "github.com/luxfi/sdk-go/ids"
)

func main() {
    // Create wallet from mnemonic
    w, err := wallet.FromMnemonic(
        "test test test test test test test test test test test junk",
        "mainnet",
    )
    if err != nil {
        log.Fatal(err)
    }

    ctx := context.Background()

    // Check X-Chain balance
    balance, err := w.XBalance(ctx, ids.LUXAssetID)
    if err != nil {
        log.Fatal(err)
    }
    log.Printf("X-Chain balance: %d nLUX", balance)

    // Send LUX on X-Chain
    recipient, _ := ids.ShortFromString("X-lux1...")
    txID, err := w.SendX(ctx, recipient, 1000000000, ids.LUXAssetID)
    if err != nil {
        log.Fatal(err)
    }

    // Wait for confirmation
    if err := w.WaitForAccepted(ctx, txID); err != nil {
        log.Fatal(err)
    }

    log.Printf("Transaction accepted: %s", txID)
}
\end{lstlisting}

\section{Related Work}

The Lux Go SDK builds on prior work in blockchain client libraries. The go-ethereum library~\cite{geth} established patterns for typed RPC clients and transaction signing. The Bitcoin btcd project~\cite{btcd} demonstrated efficient UTXO handling in Go. Our SDK extends these concepts to Lux's multi-chain architecture.

\section{Conclusion}

The Lux Go SDK provides a performant, type-safe client library for Lux blockchain development. Key contributions include:

\begin{itemize}
    \item Typed identifiers preventing misuse at compile time
    \item Efficient transaction builders for all three chains
    \item HD wallet with BIP-44 derivation
    \item Concurrent UTXO fetching for large address sets
    \item Comprehensive error types for graceful failure handling
\end{itemize}

The SDK serves as the reference implementation for language bindings in JavaScript, Rust, and Python. Future work includes WebSocket subscriptions for real-time updates and hardware wallet integration.
