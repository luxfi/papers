\subsection{Wire format unchanged}

The QuasarCert struct shape (LP-182) is the same across all modes.
The operator's mode choice is a header byte on the runtime config,
NOT a wire format change. Relying parties parse the cert and apply
mode policy locally.

\section{Activation Marker}

\begin{verbatim}
activates:      2025-12-25T16:20:00-08:00
activates-unix: 1766708400
\end{verbatim}

The 4-mode ladder is the operator-facing surface from activation
forward. The codenames remain valid internal identifiers and are
not ripped from the codebase.

\section{Backwards Compatibility}

None. The codenames remain as INTERNAL identifiers --
operator config tooling, dashboards, and docs use the mode
names. Code that references \texttt{polaris.go}'s
\texttt{PolarisLegs} struct or \texttt{IsPolaris} /
\texttt{HasHashBased} predicates is unaffected: those are
internal-API surfaces, not operator-facing.

A chain genesis published before activation cannot use the mode
names. Pre-activation chains are on the pre-Quasar Edition Lux
network and are out of scope for this LP entirely.

\section{Security Considerations}

The mode ladder does not change the cryptographic guarantees of any
individual leg. Mode security is the floor of the strongest leg in
the required set -- the same property LP-017 stated for cert
profiles.

The mode names declare posture explicitly. An operator who picks
\texttt{PQ-off} is making an informed declaration that their
threat model excludes store-now-decrypt-later adversaries; the
codename ``Pulsar'' did not make that declaration nearly as
legibly. This is a security property of the SPEC SURFACE, not the
protocol -- but operator-error reduction is a real security
concern at the human layer.

The pure-PQ variants drop BLS. A chain at \texttt{strict-PQ-*}
cannot interoperate with any relying party that requires BLS in
the cert; the relying party will see an empty BLS leg and degrade
per LP-202. This is intended -- pure-PQ chains are explicit about
not consuming BLS.
