\begin{abstract}
We specify the KZG polynomial commitment precompile on the Lux EVM, implementing
the point evaluation and blob verification operations from EIP-4844
(Proto-Danksharding). KZG commitments~\cite{kzg} enable a prover to commit to a
polynomial $p(x)$ with a single elliptic curve point and later prove that $p(z) = y$
for any evaluation point $z$ with a single group element proof, verifiable via
one pairing check. The precompile supports: (i) point evaluation verification
(EIP-4844 \texttt{POINT\_EVALUATION\_PRECOMPILE}), (ii) blob-to-KZG commitment,
and (iii) multi-point opening verification for data availability sampling.
Gas costs range from 50\,000 for a single point evaluation to 180\,000 for
blob commitment, reflecting the pairing and MSM operations involved. The
trusted setup uses the Ethereum KZG Ceremony output (powers of tau for
$n = 4096$).
\end{abstract}

\section{Introduction}

KZG (Kate-Zaverucha-Goldberg) polynomial commitments~\cite{kzg} are the
foundation of Ethereum's data availability layer (EIP-4844, Danksharding).
A KZG commitment to polynomial $p(x) = \sum_{i=0}^{d} a_i x^i$ is:
\[
  C = [p(\tau)] G_1 = \sum_{i=0}^{d} a_i [\tau^i] G_1
\]
where $\tau$ is the secret from the trusted setup (unknown to all parties) and
$[\tau^i] G_1$ are the structured reference string (SRS) elements.

On Lux, KZG commitments serve:
\begin{enumerate}[label=(\roman*)]
  \item \textbf{Data availability}: Blob transactions with KZG commitments
    for rollup data.
  \item \textbf{zkEVM proof composition}: KZG opening proofs as inputs to
    recursive SNARKs.
  \item \textbf{State diff compression}: Merkle-to-KZG migration for
    stateless clients.
\end{enumerate}

\section{Trusted Setup}

The precompile uses the output of the Ethereum KZG Ceremony (2023), providing
SRS elements $\{[\tau^i] G_1\}_{i=0}^{4095}$ and $[\tau] G_2$. The ceremony
had 141\,416 contributors; the setup is secure if at least one contributor
deleted their toxic waste.

\begin{definition}[Structured Reference String]
$\text{SRS} = (\{[\tau^i]_1\}_{i=0}^{n-1}, [\tau]_2)$ where:
\begin{itemize}
  \item $[\tau^i]_1 \in G_1$ are the evaluation key points.
  \item $[\tau]_2 \in G_2$ is used in the verification pairing.
  \item $n = 4096$ (degree bound, matching EIP-4844 blob size of 4096 field elements).
\end{itemize}
\end{definition}

\subsection{Point Evaluation (EIP-4844)}

\textbf{Input}: Versioned hash (32 bytes), evaluation point $z$ (32 bytes),
claimed value $y$ (32 bytes), commitment $C$ (48 bytes), proof $\pi$ (48 bytes).

\textbf{Output}: On success, returns the BLS modulus $p$ and the scalar field order $r$
as two 32-byte values (EIP-4844 compatibility). On failure, returns error.

\textbf{Verification equation}:
\[
  e(\pi, [\tau]_2 - [z]_2) = e(C - [y]_1, [1]_2)
\]

Equivalently: $e(\pi, [\tau - z]_2) \cdot e([y]_1 - C, [1]_2) = 1_{G_T}$.

\begin{theorem}[Soundness]
Under the $d$-Strong Diffie-Hellman assumption over BLS12-381, no PPT adversary
can produce a valid proof $\pi$ for an incorrect evaluation $y \neq p(z)$ with
non-negligible probability.
\end{theorem}

\subsection{Blob to Commitment}

\textbf{Input}: 131\,072 bytes (4096 BLS12-381 scalar field elements, each 32 bytes).

\textbf{Output}: 48 bytes (compressed G1 point).

Computes $C = \sum_{i=0}^{4095} a_i \cdot [\tau^i]_1$ via MSM over the SRS.

\subsection{Multi-Opening Verification}

Verifies multiple evaluation proofs simultaneously using random linear combination.
Given $k$ claims $(z_j, y_j, \pi_j)$ against commitment $C$:

\[
  e\!\left(\sum_{j=1}^{k} r_j \pi_j, [\tau]_2\right) =
  e\!\left(\sum_{j=1}^{k} r_j (z_j \pi_j + [y_j]_1) - C \cdot \sum r_j, [1]_2\right)
\]

where $r_j$ are random challenge scalars derived from the Fiat-Shamir transcript.

\section{Security Analysis}

\subsection{Trusted Setup Dependency}

KZG security requires the $\tau$-trapdoor to be unknown. The Ethereum ceremony's
141\,416 participants provide a strong 1-of-$N$ trust assumption. However, the
trusted setup is a fundamental limitation: if all contributors collude (or a
quantum computer factors the discrete log), the scheme breaks.

\subsection{Commitment Binding}

Under the discrete log assumption on BLS12-381, the KZG commitment is
computationally binding: no efficient adversary can find two distinct polynomials
$p \neq q$ with $[p(\tau)]_1 = [q(\tau)]_1$.

\subsection{Versioned Hash}

The EIP-4844 point evaluation precompile verifies that the input versioned hash
matches SHA-256 of the commitment (prefixed with version byte \texttt{0x01}).
This binds the proof to a specific blob transaction.

The point evaluation is dominated by a single pairing check (same cost as the
BLS12-381 pairing precompile). Blob commitment requires MSM over 4096 points,
benefiting from Pippenger's algorithm.

\section{Conclusion}

The KZG precompile brings Ethereum-compatible data availability primitives to the
Lux EVM. The EIP-4844 point evaluation is fully compatible with Ethereum blob
transactions. The multi-opening variant enables efficient data availability
sampling for rollup verification. Gas costs track the underlying pairing and
MSM computation within a factor of 1.2.
