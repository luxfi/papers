\section{System Definition}

Teleport is an \textbf{omnichain collateralized credit and settlement protocol}. It is not a bridge, vault, stablecoin, or liquid staking token.

The system comprises four subsystems, each audited against different failure classes:

\begin{enumerate}[leftmargin=2em]
\item \textbf{Collateral custody}: Vault contracts holding base assets (ETH, BTC, etc.)
\item \textbf{Credit issuance}: Minting/burning credit tokens (LETH, LBTC) against collateral
\item \textbf{Transport/finality}: Cross-chain message passing with MPC attestation
\item \textbf{Surplus allocation}: Yield distribution to protocol equity holders (xLUX)
\end{enumerate}

\section{Asset Taxonomy}

\subsection{Class 1: Credit Assets}

\textit{Examples: LETH, LBTC}

\begin{quote}
A credit asset is an overcollateralized, in-kind redeemable liability of the protocol, minted against vault-backed base assets subject to a hard LTV cap.
\end{quote}

Required properties:
\begin{itemize}[leftmargin=2em]
\item Minted only against recognized backing
\item Redeemable 1:1 in kind
\item Hard issuance cap at or below configured LTV
\item No direct claim on strategy yield
\item No governance, profit-share, or security rights
\end{itemize}

\textbf{Constraint (enforced technically and legally):}
$$\texttt{creditAsset} \neq \texttt{yieldShare} \neq \texttt{securityToken}$$

Enforcement:
\begin{itemize}[leftmargin=2em]
\item Separate token contracts
\item Separate registries
\item Separate accounting buckets
\item Separate docs and disclosures
\end{itemize}

\textbf{Canonical definition of LETH:}

\begin{quote}
LETH is a protocol-issued, fully collateralized, in-kind redeemable credit token backed by ETH vault assets and minted subject to a hard maximum loan-to-value ratio of 90\%, with strategy yield accruing to protocol surplus rather than to LETH holders.
\end{quote}

\subsection{Class 2: Yield/Equity Instruments}

\textit{Examples: xLUX, protocol equity accounting unit}

\begin{quote}
A yield/equity instrument represents a claim on protocol surplus, not on redemption principal backing.
\end{quote}

Required properties:
\begin{itemize}[leftmargin=2em]
\item Absorbs upside from strategy earnings
\item May absorb losses after buffer rules, depending on design
\item Never used as collateral equivalence for redemptions unless explicitly approved
\end{itemize}

\subsection{Class 3: Security Assets}

\textit{Examples: tokenized equity, funds, RWAs}

\begin{quote}
A security asset is issued and controlled under the ATS/compliance layer and is not fungible with protocol credit liabilities.
\end{quote}

Required properties:
\begin{itemize}[leftmargin=2em]
\item Compliance-enforced transferability
\item Lockup / whitelist logic
\item Jurisdictional controls
\item Separate wrapping policy when bridged into Lux
\end{itemize}

\section{Bridge Message Schema}

\subsection{Message Types}

\begin{center}
\begin{tabular}{ll}
\toprule
\textbf{Type} & \textbf{Purpose} \\
\midrule
\texttt{DEPOSIT\_V1} & Lock base asset, request credit mint on destination \\
\texttt{BURN\_V1} & Burn credit token, request base asset release \\
\texttt{RELEASE\_V1} & Release base asset from vault \\
\texttt{BACKING\_V1} & Attest current backing state \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Common Envelope}

\begin{verbatim}
MessageEnvelope {
    version:         uint8
    messageType:     bytes4
    srcChainId:      uint256
    dstChainId:      uint256
    routerAddress:   address
    assetId:         bytes32
    nonce:           uint256
    amount:          uint256
    recipient:       address
    expiry:          uint256
    originTxHash:    bytes32    // source event identifier
    payloadHash:     bytes32    // canonical hash of typed payload
    domainSeparator: bytes32    // chain + deployment + protocol version
}
\end{verbatim}

The \texttt{domainSeparator} closes replay classes:
\begin{itemize}[leftmargin=2em]
\item Chain replay
\item Deployment replay
\item Router migration replay
\item Same-signature / different-context reuse
\item Duplicated source event processing
\end{itemize}

\subsection{Verification Rules}

Every receive path MUST check:

\begin{enumerate}[leftmargin=2em]
\item \texttt{block.timestamp <= expiry}
\item \texttt{dstChainId == currentChainId}
\item \texttt{routerAddress == localRouter}
\item Nonce unused for \texttt{(srcChainId, routerAddress, assetId)}
\item \texttt{amount > 0}
\item \texttt{recipient != address(0)}
\item \texttt{assetId} recognized and enabled
\item Message hash signed under current authorized signer set
\end{enumerate}

\section{Invariants}

\subsection{Definitions}

Let:
\begin{itemize}[leftmargin=2em]
\item $B$ = total backing value of redeemable vault assets
\item $L$ = total outstanding credit liabilities
\item $E = B - L$ = protocol equity
\end{itemize}

\subsection{Core Issuance Invariant}

$$L \leq \texttt{issuanceLtvCap} \times B$$

For LETH at 90\% max LTV:
$$L \leq 0.9 \times B$$

\subsection{Redemption Invariant}

$$\texttt{burn}(x \text{ LETH}) \Rightarrow \texttt{release}(x \text{ ETH})$$

Subject only to:
\begin{itemize}[leftmargin=2em]
\item Finality delay (per-chain confirmation threshold)
\item Operational pause (emergency state only)
\item Sanctions/compliance constraints where applicable
\end{itemize}

\subsection{Parity Invariant}

$$\text{redeemable principal per unit of LETH} = 1 \text{ ETH}$$

\subsection{Equity Ratio}

$$\frac{E}{B} \geq 10\%$$

Equivalently under a 90\% LTV model:
$$\frac{L}{B} \leq 90\%$$

\section{Solvency State Machine}

\subsection{States}

\begin{center}
\begin{tabular}{llp{7cm}}
\toprule
\textbf{State} & \textbf{Condition} & \textbf{Description} \\
\midrule
\textsc{Healthy} & $B \geq L / 0.9$ and $B \geq L$ & Normal operation \\
\textsc{RestrictedMint} & $B < L / 0.9$ but $B \geq L$ & Overcollateralization violated, principal intact \\
\textsc{Emergency} & $B < L$ & Undercollateralized on principal basis \\
\textsc{Recovery} & Governance-initiated & Recapitalization in progress \\
\bottomrule
\end{tabular}
\end{center}

Auto-pause threshold:
$$B < 0.985 \times L \Rightarrow \textsc{Emergency}$$

\subsection{Allowed Transitions}

\begin{verbatim}
HEALTHY
  -> RESTRICTED_MINT    (B drops below L/0.9)
  -> EMERGENCY          (B drops below L, or B < 0.985*L)

RESTRICTED_MINT
  -> HEALTHY            (B recovers above L/0.9)
  -> EMERGENCY          (B drops below L)

EMERGENCY
  -> RECOVERY           (governance vote or MPC action)

RECOVERY
  -> HEALTHY            (recapitalization complete, invariants restored)
\end{verbatim}

\subsection{Per-State Permissions}

\begin{center}
\begin{tabular}{lccccc}
\toprule
\textbf{Action} & \textbf{Healthy} & \textbf{Restricted} & \textbf{Emergency} & \textbf{Recovery} \\
\midrule
Mint credit tokens & \checkmark & $\times$ & $\times$ & $\times$ \\
Burn credit tokens & \checkmark & \checkmark & \checkmark & \checkmark \\
Release base assets & \checkmark & \checkmark & Queue$^*$ & Queue$^*$ \\
Strategy deposits & \checkmark & $\times$ & $\times$ & $\times$ \\
Strategy withdrawals & Normal & Accelerated & Forced & Forced \\
ATS wrapping & \checkmark & \checkmark & $\times$ & $\times$ \\
\bottomrule
\end{tabular}
\end{center}

$^*$In Emergency/Recovery, releases enter a FIFO queue processed as backing becomes available.

\subsection{State Transition Authority}

\begin{itemize}[leftmargin=2em]
\item \textsc{Healthy} $\to$ \textsc{RestrictedMint}: Automatic (contract-enforced)
\item \textsc{RestrictedMint} $\to$ \textsc{Emergency}: Automatic (contract-enforced)
\item \textsc{Emergency} $\to$ \textsc{Recovery}: MPC quorum (T-of-N threshold)
\item \textsc{Recovery} $\to$ \textsc{Healthy}: MPC quorum + invariant verification
\end{itemize}

\section{Failure Behavior}

\subsection{MPC Halt}

\textbf{Mode B (user-executable fallback):}
\begin{itemize}[leftmargin=2em]
\item After timeout $T$, users can prove burn on source chain and self-relay on destination
\item Release executes from pre-authorized fallback path
\item No liveness dependency on MPC signer availability
\end{itemize}

This provides institution-grade guarantees: user funds are never permanently locked by signer unavailability.

\subsection{Stale Backing Report}

$$\texttt{maxBackingReportAge} = X \text{ seconds}$$

Policy:
\begin{itemize}[leftmargin=2em]
\item If stale: disable mint
\item Allow burn and release against last confirmed backing unless in \textsc{Emergency} state
\item Emit \texttt{BackingStale} status event
\end{itemize}

Asymmetry: stop issuance first, preserve exits as long as possible.

\subsection{Strategy Loss}

Loss waterfall:
\begin{enumerate}[leftmargin=2em]
\item Realized/unrealized loss hits surplus buffer ($E$)
\item If buffer exhausted: system enters \textsc{RestrictedMint}
\item If principal backing threatened: \textsc{Emergency}
\item New deployment to strategies halted until recapitalization
\end{enumerate}

\subsection{Chain Reorg / Finality}

Per chain, define:
$$\texttt{minFinalityConfirmations}[\texttt{chainId}]$$

Mint/release occurs only after finality threshold for source events. No global constant across chains.

\subsection{Oracle / Valuation Failure}

Policy:
\begin{itemize}[leftmargin=2em]
\item Freeze mint for affected asset
\item Allow only like-for-like redemption where backing is directly observable
\item Disable cross-asset accounting based on stale prices
\end{itemize}

\section{ATS Boundary}

\begin{quote}
A security token may be transported into Lux only through a wrapper whose compliance posture is explicitly declared and enforced at the wrapper level.
\end{quote}

\subsection{Strict Wrapper Model (Recommended)}

$$\texttt{ATS\_SECURITY} \to \texttt{Restricted\_Wrapped\_Security}$$

Properties preserved:
\begin{itemize}[leftmargin=2em]
\item Whitelist enforced
\item Transfer restrictions preserved
\item Lockups preserved
\item DeFi composability limited by design
\end{itemize}

The dual wrapper model (restricted $\to$ composable) is deferred until policy and counsel are settled. Start strict.

\section{Open Questions (Pre-Audit)}

Two spots require exact wording before audit:

\begin{enumerate}[leftmargin=2em]
\item \textbf{Stale backing + redemptions}: Whether redemptions remain permissionless during stale-backing conditions.\\
\textit{Recommendation: stop mint, preserve exits.}

\item \textbf{Emergency undercollateralization}: Whether releases pause entirely or shift to queue/pro-rata/governance-controlled mode.\\
\textit{Recommendation: stop mint, preserve claim ordering through an explicit emergency redemption policy (FIFO queue).}
\end{enumerate}

These are core user-rights definitions, not implementation details.
