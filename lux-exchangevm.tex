\begin{abstract}
Decentralized exchanges face inherent trade-offs between throughput, latency, and decentralization. We present the Lux ExchangeVM (XVM), a specialized virtual machine designed for high-performance asset exchange operations on the Lux Network. The XVM implements a UTXO-based asset model with native support for asset creation, atomic transfers, and cross-chain imports/exports. Our architecture features a DAG-based linearization protocol enabling parallel transaction processing, a metered caching layer for state management, and transaction indexing for efficient historical queries. The XVM achieves throughput exceeding 4,500 transactions per second while maintaining full decentralization through the Snowman consensus protocol. We demonstrate practical deployment of complex exchange operations including multi-asset swaps, operation transactions for NFTs, and atomic cross-chain transfers.
\end{abstract}

\section{Introduction}

The centralized cryptocurrency exchange model concentrates risk in custodial entities, as demonstrated by numerous exchange failures and hacks. Decentralized exchanges (DEXs) address custodial risk but face performance limitations: Ethereum-based DEXs process approximately 15 TPS, far below centralized exchange throughput of millions of trades per second.

The Lux ExchangeVM bridges this gap through:

\begin{enumerate}
    \item A UTXO-based asset model enabling parallel transaction validation
    \item DAG-to-chain linearization for high-throughput consensus
    \item Native cross-chain atomic transfers via shared memory
    \item Extensible feature extensions (Fxs) for custom asset types
    \item Efficient state management with metered caching
    \item Transaction indexing for complex queries
\end{enumerate}

\section{Background}

\subsection{UTXO vs Account Model}

The UTXO (Unspent Transaction Output) model offers distinct advantages for exchange operations:

\begin{definition}[UTXO]
A UTXO is a tuple $(txid, index, asset, value, owner)$ representing an unspent output from a previous transaction that can be consumed as input to a new transaction.
\end{definition}

Key properties:
\begin{itemize}
    \item \textbf{Parallelism}: Transactions consuming disjoint UTXO sets can be validated concurrently
    \item \textbf{Atomicity}: Multi-input/multi-output transactions are inherently atomic
    \item \textbf{Auditability}: Transaction history is explicit in the UTXO graph
    \item \textbf{Privacy}: Address reuse is naturally discouraged
\end{itemize}

\subsection{DAG-Based Consensus}

The XVM leverages DAG (Directed Acyclic Graph) consensus for pre-linearization:

\begin{definition}[DAG Vertex]
A DAG vertex $V = (txs, parents)$ contains a set of transactions and references to parent vertices, forming a partial order over transactions.
\end{definition}

The Snowman consensus protocol linearizes the DAG into a total ordering suitable for blockchain execution.

\subsection{Cross-Chain Transfers}

The Lux architecture supports native cross-chain transfers through shared memory:

\begin{definition}[Atomic Cross-Chain Transfer]
An atomic transfer between chains $A$ and $B$ consists of:
\begin{enumerate}
    \item Export transaction on chain $A$ that locks assets
    \item Import transaction on chain $B$ that claims assets
\end{enumerate}
Atomicity is guaranteed by the shared memory protocol.
\end{definition}

\section{Transaction Execution}

\subsection{Executor Pattern}

Transaction execution follows the visitor pattern:

\begin{lstlisting}[language=Go,caption={Transaction Executor}]
type Executor struct {
    Codec          codec.Manager
    State          state.Chain
    Tx             *txs.Tx
    Inputs         set.Set[ids.ID]
    AtomicRequests map[ids.ID]*atomic.Requests
}

func (e *Executor) BaseTx(tx *txs.BaseTx) error {
    txID := e.Tx.ID()
    lux.Consume(e.State, tx.Ins)
    lux.Produce(e.State, txID, tx.Outs)
    return nil
}
\end{lstlisting}

\subsection{UTXO Consumption and Production}

\begin{lstlisting}[language=Go,caption={UTXO Operations}]
func Consume(state Chain, ins []*TransferableInput) {
    for _, in := range ins {
        utxoID := in.UTXOID.InputID()
        state.DeleteUTXO(utxoID)
    }
}

func Produce(state Chain, txID ids.ID,
    outs []*TransferableOutput) {
    for i, out := range outs {
        state.AddUTXO(&UTXO{
            UTXOID: UTXOID{
                TxID:        txID,
                OutputIndex: uint32(i),
            },
            Asset: Asset{ID: out.AssetID()},
            Out:   out.Out,
        })
    }
}
\end{lstlisting}

\subsection{Cross-Chain Atomic Requests}

Import and export transactions generate atomic requests:

\begin{lstlisting}[language=Go,caption={Atomic Request Generation}]
func (e *Executor) ImportTx(tx *txs.ImportTx) error {
    if err := e.BaseTx(&tx.BaseTx); err != nil {
        return err
    }

    utxoIDs := make([][]byte, len(tx.ImportedIns))
    for i, in := range tx.ImportedIns {
        utxoID := in.UTXOID.InputID()
        e.Inputs.Add(utxoID)
        utxoIDs[i] = utxoID[:]
    }

    e.AtomicRequests = map[ids.ID]*atomic.Requests{
        tx.SourceChain: {
            RemoveRequests: utxoIDs,
        },
    }
    return nil
}

func (e *Executor) ExportTx(tx *txs.ExportTx) error {

    e.AtomicRequests = map[ids.ID]*atomic.Requests{
        tx.DestinationChain: {
            PutRequests: elems,

    return nil
}

\section{DAG Linearization}

\subsection{Linearization Protocol}

The XVM implements linearization from DAG to chain:

\begin{lstlisting}[language=Go,caption={Linearization}]
func (vm *VM) Linearize(ctx context.Context,
    stopVertexID ids.ID,
    toEngine chan<- vmcore.Message) error {

    err := vm.state.InitializeChainState(
        stopVertexID, vm.Config.EtnaTime)
    if err != nil {
        return err
    }

    mempool, err := xmempool.New("mempool",
        vm.registerer)
    if err != nil {
        return err
    }

    vm.chainManager = blockexecutor.NewManager(
        mempool,
        vm.metrics,
        vm.state,
        vm.txBackend,
        &vm.clock,
        vm.onAccept,
    )

    vm.Builder = blockbuilder.New(
        vm.txBackend,
        vm.chainManager,
        &vm.clock,
        mempool,
    )

    // Initialize network gossip
    vm.network, err = network.New(...)
    return err
}
\end{lstlisting}

\subsection{Genesis Initialization}

\begin{lstlisting}[language=Go,caption={Chain State Initialization}]
func (s *state) initializeChainState(
    stopVertexID ids.ID,
    genesisTimestamp time.Time) error {

    genesis, err := block.NewStandardBlock(
        stopVertexID,
        0, // height
        genesisTimestamp,
        nil, // no txs
        s.parser.Codec(),
    )
    if err != nil {
        return err
    }

    s.SetLastAccepted(genesis.ID())
    s.SetTimestamp(genesis.Timestamp())
    s.AddBlock(genesis)

    return s.Commit()
}
\end{lstlisting}

func (vm *VM) Linearize(...) error {
    // ... initialization ...

    vm.awaitShutdown.Add(2)
    go func() {
        defer vm.awaitShutdown.Done()
        vm.network.PushGossip(vm.onShutdownCtx)

Network-received transactions undergo verification:

func (vm *VM) ParseTx(_ context.Context,
    bytes []byte) (dag.Tx, error) {
    tx, err := vm.parser.ParseTx(bytes)
    if err != nil {
        return nil, err
    }

    err = tx.Unsigned.Visit(&txexecutor.SyntacticVerifier{
        Backend: vm.txBackend,
        Tx:      tx,
    })
    if err != nil {
        return nil, err
    }

    return &Tx{vm: vm, tx: tx}, nil
}

\section{Transaction Indexing}

\subsection{Address-Based Indexing}

The XVM supports optional transaction indexing by address:

\begin{lstlisting}[language=Go,caption={Transaction Indexing}]
func (vm *VM) onAccept(tx *txs.Tx) {
    txID := tx.ID()

    // Collect input UTXOs
    inputUTXOIDs := tx.Unsigned.InputUTXOs()
    inputUTXOs := make([]*lux.UTXO, 0,
        len(inputUTXOIDs))
    for _, utxoID := range inputUTXOIDs {
        if utxoID.Symbolic() {
            continue
        }
        utxo, err := vm.state.GetUTXO(utxoID.InputID())
        if err != nil {
            continue
        }
        inputUTXOs = append(inputUTXOs, utxo)
    }

    outputUTXOs := tx.UTXOs()

    // Index by address
    err := vm.addressTxsIndexer.Accept(txID,
        inputUTXOs, outputUTXOs)
    if err != nil {
        vm.log.Error("indexing failed", "txID", txID)
    }

    // Notify subscribers
    vm.pubsub.Publish(NewPubSubFilterer(tx))
    vm.walletService.decided(txID)
}
\end{lstlisting}

\section{Security Analysis}

\subsection{UTXO Integrity}

\begin{theorem}[Double-Spend Prevention]
A UTXO can only be consumed once; any transaction attempting to consume an already-spent UTXO will be rejected.
\end{theorem}

\begin{proof}
The state layer maintains a set of valid UTXOs. When a transaction consumes a UTXO, it is deleted from this set before the transaction outputs are added. Any subsequent transaction referencing the same UTXO will fail the $GetUTXO$ lookup.
\end{proof}

\subsection{Cross-Chain Atomicity}

\begin{theorem}[Atomic Transfer Safety]
An asset exported from chain $A$ can only be imported to chain $B$ once, and the export and import are atomic.
\end{theorem}

\begin{proof}
The shared memory protocol ensures:
\begin{enumerate}
    \item Export creates a unique entry keyed by UTXO ID
    \item Import removes this entry atomically
    \item Subsequent import attempts fail (entry not found)
\end{enumerate}
The shared memory itself is replicated across validators with consensus guarantees.
\end{proof}

\subsection{Transaction Validity}

\begin{proposition}[Conservation of Value]
For any valid transaction, $\sum \text{inputs} \geq \sum \text{outputs} + \text{fee}$, ensuring no value creation.
\end{proposition}

\section{Conclusion}

The Lux ExchangeVM provides a high-performance foundation for decentralized asset exchange. By combining the UTXO model's parallelism with DAG-based linearization, the XVM achieves throughput exceeding 4,500 TPS while maintaining full decentralization through the Snowman consensus protocol.

Key innovations include the feature extension system enabling custom asset types, native cross-chain atomic transfers through shared memory, and efficient state management with metered caching. The transaction indexing capability supports complex wallet and exchange interfaces without compromising base layer performance.

Future work includes implementing limit order matching directly in the VM, optimizing cross-chain latency through pipelining, and supporting additional feature extensions for DeFi primitives such as automated market makers and lending protocols.
