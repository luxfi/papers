\section{Discussion}


\subsection{When to Use GPU EVM}

The crossover analysis (Table~\ref{tab:crossover}) provides a clear decision rule:

\begin{itemize}
\item \textbf{Below 500 ops/tx}: CPU wins. Simple transfers and token operations
      do not generate enough parallel work to amortize GPU launch overhead.
\item \textbf{500--2{,}000 ops/tx}: Marginal GPU advantage (1.0--2.08$\times$).
      Worth offloading only if the GPU is not otherwise occupied.
\item \textbf{Above 2{,}000 ops/tx}: Clear GPU advantage. Uniswap swaps ($\sim$3{,}000 ops),
      complex DeFi ($>$5{,}000 ops), and ZK verification ($>$10{,}000 ops) all benefit.
\item \textbf{Peak}: 50k transactions $\times$ 5k opcodes each: 4.85$\times$.
\end{itemize}

\subsection{The Optimization Priority Stack}

Based on measured data, the priority order for EVM acceleration is:

\begin{enumerate}
\item \textbf{Parallel ecrecover} (7.1$\times$ on 87\% of time = 3.76$\times$ overall).
      Implemented. Deployed.
\item \textbf{C++ interpreter} (5.1$\times$ on 13\% of time = 1.12$\times$ overall).
      Implemented. The marginal gain is small because EVM execution is not the bottleneck.
\item \textbf{GPU opcodes} (4.85$\times$ on complex contracts). Highest impact on
      computation-heavy workloads where per-transaction opcode count exceeds 2{,}000.
\item \textbf{Block-STM} (6.4$\times$ on 10 threads for independent transactions).
      Orthogonal to the above; parallelizes across transactions rather than within them.
\end{enumerate}

\subsection{Memory Budget}

GPU memory is the practical scaling constraint. At 73\,KB per transaction plus 5\,GB
persistent state, the memory budget determines maximum block size:

\begin{itemize}
\item \textbf{32\,GB system}: $(32 - 5) / 0.073 \approx 370{,}000$ tx/block
\item \textbf{64\,GB system}: $(64 - 5) / 0.073 \approx 800{,}000$ tx/block
\item \textbf{128\,GB (M4 Ultra)}: $(128 - 5) / 0.073 \approx 1{,}685{,}000$ tx/block
\end{itemize}

With BLS consensus aggregate verify at $16.51\times$ at $n{=}1024$
on the same-message hot path (cevm v0.47.1, pubkey-decompression cache

theoretical throughput ceiling is:
\begin{equation}
\text{TPS}_{\text{ceiling}} = \frac{47{,}619\text{ txs/block}}{10\,\text{ms}} = \num{4761904}\text{ TPS (with finality)}
\end{equation}
With 1\,ms InfiniBand interconnect replacing WAN latency, the theoretical
maximum reaches $\sim$\num{47619047} TPS.
