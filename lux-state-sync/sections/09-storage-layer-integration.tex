\section{Storage Layer Integration}

\subsection{Database Schema}

Synced state is stored in a key-value database (LevelDB or Pebble):

\begin{table}[H]
\centering
\caption{Database key prefixes for synced state.}
\label{tab:db}
\begin{tabular}{lll}
\toprule
\textbf{Prefix} & \textbf{Key Format} & \textbf{Value} \\
\midrule
\texttt{a/} & Account hash & RLP-encoded account \\
\texttt{s/} & Account hash + slot hash & Storage value \\
\texttt{c/} & Code hash & Contract bytecode \\
\texttt{n/} & Trie node hash & RLP-encoded trie node \\
\texttt{m/} & Sync metadata key & Progress, roots \\
\bottomrule
\end{tabular}
\end{table}

\subsection{Write Amplification}

\begin{proposition}[Write Amplification Bound]
Trie-aligned chunking achieves write amplification $\leq 2$: each state entry is written at most twice (once as raw data, once as trie node).
\end{proposition}

This is an improvement over naive sync approaches where rebuilding the trie from flat state incurs write amplification of $O(d)$ due to intermediate node recomputation.
