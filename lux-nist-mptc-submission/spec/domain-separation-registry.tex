\section*{Abstract}

\noindent We present Lux, a hybrid post-quantum consensus architecture for DAG-native chains. Lux separates fast operational finality from durable post-quantum finality. Validators emit Photons over a Nebula DAG substrate; classical BLS aggregates form Beams for low-latency confirmation, while ML-DSA attestations and Pulsar lattice-threshold Pulses provide post-quantum finality over Nebula roots. Prism binds all certificate lanes to the same transcript, and Quasar reaches Horizon finality when the bound lanes verify.

\textbf{This document.} The complete domain-separation registry for the Lux MPTC stack. Every $\mathsf{QUASAR\text{-}*}$ / $\mathsf{PULSAR\text{-}*}$ / $\mathsf{LENS\text{-}*}$ / $\mathsf{WARP\text{-}*}$ personalization tag is enumerated, with the function it personalizes and the canonical reference. Cross-tag replay is structurally impossible by collision resistance of TupleHash256 / cSHAKE256 / KMAC256 with personalization (FIPS 202 / NIST SP 800-185).

\section{Versioning discipline}

Every personalization tag includes a version suffix (\texttt{-v1}). When a tag's semantics change, the version is bumped (\texttt{-v2}, \ldots), and the old tag remains valid for already-signed objects. There is no negotiation between versions; senders and receivers agree on the version out-of-band (typically via the chain's protocol version or the Warp envelope's wire version).

\textbf{No tag is reused across protocols.} A future $\mathsf{WARP\text{-}PULSAR\text{-}ENVELOPE\text{-}v2}$ would not collide with $\mathsf{QUASAR\text{-}PULSAR\text{-}ACTIVATE\text{-}v1}$ even if the underlying message bytes happened to coincide; the personalization tag prevents the cross-context replay.

\section{Why this matters}

\subsection{Cross-protocol replay}

Without tag separation, a Pulse over a Nebula bundle root could be lifted into a Pulse over a Warp envelope (or vice versa). The wire bytes would be syntactically distinguishable but semantically interchangeable. Tag separation makes the bytes semantically distinguishable: a TupleHash256 with one personalization is not equal to a TupleHash256 with another personalization, even on identical inputs.

This is the formal claim behind LP-073 \cite{luxpulsar} \S "Domain-separated message prefixes": the QUASAR-PULSAR-BUNDLE-v1 prefix prevents a bundle Pulse from being replayed as a Warp envelope Pulse.

\subsection{Cross-suite collision}

Pulsar-SHA3 and Pulsar-BLAKE3 use distinct personalization tags within their respective hash families. A signature produced under one suite does not verify under the other (Theorem \texttt{thm:hash-suite-separation} of \texttt{proofs/pulsar/hash-suite-separation.tex}). The HashSuiteID is bound into every transcript; cross-suite forgery would require a collision on TupleHash256 with the suite's personalization.

\subsection{Cross-version collision}

A future v2 protocol bump uses a v2 tag suffix. Signatures under v1 do not verify as v2 signatures. This is forward-only versioning: the old protocol continues to exist for already-signed objects, but the new protocol's tags are distinct.

\section{Adding a new tag}

The procedure for adding a new domain-separation tag:

\begin{enumerate}[leftmargin=2em,nosep]
  \item Choose the tag string per the LP-105 \cite{lp105} naming rules: cosmological / optical / cryptographic, Lux-owned, technically accurate.
  \item Add a versioned suffix (\texttt{-v1}).
  \item Document the tag in this registry (this file is normative).
  \item Add a test in the appropriate \texttt{*\_test.go} that verifies the tag is bound into the relevant transcript.
  \item Update the canonical reference (e.g., \texttt{proofs/definitions/transcript-binding.tex}).
\end{enumerate}

The registry is the single source of truth. A signature using a tag not in the registry is unverifiable by definition.
