\subsection{Methodology}

\paragraph{Microbenchmarks.} Run via \texttt{go test -bench=$\cdot$ -benchtime=N -count=K -benchmem ./$\cdot$/$\cdot$}. Each result is the median of $K$ runs at $N$ iterations per run. We report \emph{median}, \emph{mean}, and where relevant \emph{p99}; we do not report just-mean. Hot iterations are warmed up via Go's \texttt{Benchmark} loop semantics; cold-start measurements are flagged as such.

\paragraph{Reshare benchmarks.} Run via the LSS-Pulsar / LSS-Lens \texttt{TestDynamicReshare*} tests with timing instrumentation; the test suite runs the full $(t, n) \to (t', n')$ transition path including JVSS broadcast, lattice Pedersen verify, and activation cert. Per-party CPU time is reported; wall-clock time reflects local-loop simulation (no WAN delay) unless explicitly cross-WAN.

\paragraph{Cross-WAN projections.} Pulse latency at WAN distances is projected from local measurements plus a measured RTT distribution to Lux mainnet validator regions; Section~\ref{sec:cross-wan-latency} explains the projection. Direct cross-WAN measurements at $K=21$ are taken from the production Lux mainnet bundle-Pulse path; projections at $K \in \{64, 128\}$ are derived from the per-party Round 1 / Round 2 cost curve.

\subsection{What we did not measure}

\begin{itemize}[leftmargin=2em,nosep]
  \item GPU \emph{end-to-end} BLS aggregate verify on a Pulsar pulse path: the GPU dispatch overhead dominates at $K \leq 64$, and the production hot path runs on CPU. We measure the GPU primitive throughput (Section~\ref{sec:gpu-headroom}); the end-to-end production GPU path is research, not production.
  \item Adversarial network conditions: the cross-WAN measurements assume honest validator behavior over commodity internet. Adversarial-delay scenarios are not in the production benchmark surface.
  \item Cold-start full-chain restart: we benchmark the steady-state operations the chain runs every block / bundle, not the ceremony-startup or chain-bootstrap path.
\end{itemize}

\subsection{Reproducibility}

The KAT regen scripts (\texttt{pulsar/scripts/regen-kats.sh}) produce byte-equal outputs across runs. The fuzz harnesses (\texttt{warp/pulsar/fuzz\_*.go}, \texttt{warp/fuzz\_envelope\_test.go}) return zero panics in 60 s. Every table below is reproducible from the published canonical at the freeze tag using the listed reproduction command. Numbers in this report should match a fresh-clone run within $\pm 5\%$ on the listed hardware.
