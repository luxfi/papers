\subsubsection{Backend dispatch boundary}

The Go layer is intentionally thin: $\sim$\SI{70}{LOC} of
\texttt{Run()} body is structural parsing and pre-filter; the heavy
lifting (FRI verify, cSHAKE256 Merkle openings, Goldilocks
arithmetic) happens in the audited Rust verifier crate at
\texttt{lux/p3q/crates/p3q-verifier}, reached through
\texttt{RegisterVerifier} at node startup. The cgo bridge is out of
scope of LP-221 (it is a node-build detail) and is gated by an
external audit per the sign-off's GATE-4.

The atomic-load pattern on the verifier function pointer means a
node operator can hot-swap the backend without restarting the
precompile (e.g., to roll out a verifier patch in a coordinated
upgrade window); concurrent calls observe either the pre-swap or
post-swap function value, never a torn read.

\subsection{Jasmin reference and status-code table}

The Jasmin reference at \texttt{lux/precompile/starkfri/jasmin/verify.jazz}
(\SI{14.2}{\kilo\byte}) covers the structural pre-dispatch gate
only: length checks, version byte, magic-header equality via the
XOR-accumulator \texttt{ct\_check\_magic}. The FRI verify inner
loop is delegated to the Rust verifier crate; Jasmin owns the
boundary that EasyCrypt reasons about.

\subsubsection{CT annotation}

The CT annotation in the Jasmin source is:

\begin{lstlisting}[language={}]
#[ct = "public * public * public * public -> public"]
\end{lstlisting}

All four arguments and the return value are tagged \texttt{public}.
This is consistent with the threat model: STARK proofs and their
public inputs are non-secret by construction. The CT annotation is
load-bearing for soundness rather than confidentiality (see
Section~\ref{sec:constant-time}).

\label{tab:ec-admits}

The budget is enforced by a per-push CI check; any new \texttt{admit}
token in any of the four files breaks the build. The
zero-admit budget means every theorem in the theory either
discharges to a Lean / EasyCrypt primitive, to a backend axiom
explicitly named in the theory, or to a structural-Jasmin
correspondence claim.

The key theorem is \texttt{accept\_iff\_backend\_accept} in
\texttt{P3Q\_Verifier.ec}:

\begin{quote}
\emph{For every input \texttt{calldata}, every gas-in
\texttt{gas\_in $\ge$ RequiredGas(calldata)}, and every registered
backend \texttt{B}: the precompile returns
$(\texttt{output}, \_, \texttt{nil})$ on calldata if and only if the
backend $B$ accepts $(\texttt{version=0x01}, \texttt{proof}, \texttt{pub})$
extracted from \texttt{calldata} per the wire-format parse.}
\end{quote}

The theorem reduces precompile soundness to backend soundness; the
backend's soundness is the standard STARK / FRI knowledge soundness
under the random-oracle model.

\subsection{Sign-off gates}

The internal cryptographer sign-off
(\texttt{CRYPTOGRAPHER-SIGN-OFF.md} in the precompile package)
verdict is \textbf{APPROVED WITH GATES}. The four gates are:

\begin{enumerate}[leftmargin=2em,nosep]
\item \textbf{GATE-1.} EasyCrypt admit budget pinned at $0\,/\,0$ in
  CI (\textbf{closed}; \texttt{scripts/checks/ec-admits.sh} enforces
  on every push).
\item \textbf{GATE-2.} Jasmin file passes \texttt{jasminc -checkCT}
  on every push (\textbf{closed}; integrated into
  \texttt{scripts/check-high-assurance.sh}).
\item \textbf{GATE-3.} Submission-grade dudect run
  ($10^9$~samples per stage on the structural pre-filter)
  (\textbf{open}; harness builds clean, smoke runs at
  $10^4$~samples per push are \emph{weak assertions, not
  measurements}; the production-grade run is gated on hardware
  scheduling).
\item \textbf{GATE-4.} External audit of the Rust verifier crate at
  \texttt{lux/p3q/crates/p3q-verifier} (\textbf{open}; audit
  procurement in progress).
\end{enumerate}

LP-221 ships with GATE-1 and GATE-2 closed. GATE-3 and GATE-4 are
prerequisites for moving LP-221 from Draft to Final; the slot
allocation and ABI are stable across the Draft$\to$Final
transition, only the assurance posture changes.
