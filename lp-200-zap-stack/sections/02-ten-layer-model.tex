\section{The Ten-Layer Model}
\label{sec:tenlayer}

Each row is one job. Each row consumes the layer below as a byte slice
and produces its successor as a byte slice. No layer reaches across.

The numbering goes 0--10 (eleven slots) because layer~0 is the byte
frame itself -- a property of bytes, not a layer of work. Layers 1--10
are the work.

\paragraph{Layer 0 (ZAP frame).} A ZAP frame is magic byte
\texttt{0x5A}, version byte, an 8-byte length prefix, and the object
bytes. That is the wire envelope and the storage envelope. There is
no second envelope at any other layer.

\paragraph{Layer 1 (ZapDB).} ZapDB is a Badger fork with the
\texttt{!grpc} build tag and native ZAP-typed encoders in
\texttt{pb\_zap.go}. The LSM consumes ZAP buffers directly; it does
not re-encode for storage.

\paragraph{Layer 4 (Transcript).} The cryptographic transcript is a
function from buffer to digest. It uses TupleHash256 with NIST SP
800-185 framing for unambiguous serialization of typed offsets. The
transcript and the identity hash are independent functions of the same
buffer -- changing one does not touch the other.

\paragraph{Layer 7 (Executor).} The first byte of the unsigned tx
envelope is \texttt{TxKind}. The executor is a
\texttt{map[TxKind]Handler}. There is no Visit pattern, no interface
polymorphism, no generated visitor. Adding a tx kind is one entry in
the registry; removing one is one deletion.

\paragraph{Layer 9 (Consensus).} The QuasarCert (LP-182) composes four
legs -- BLS, Pulsar, Corona, Magnetar -- as opaque ZAP byte strings.
Verify is per-leg dispatch with a leg verifier per leg type; no leg
verifier knows about another leg. The operator-facing mode names
(LP-217) describe which legs are required for a given posture.
