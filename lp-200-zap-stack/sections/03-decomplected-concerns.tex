\section{Ten Decomplected Concerns}

Ten things that the legacy stack braided, unbraided here. Each is one
layer's job. Each layer reads bytes and writes bytes; nothing reaches
across.

\subsection{Wire $\leftrightarrow$ in-memory $\leftrightarrow$ on-disk}

Legacy: three Go structures -- wire DTO, runtime struct, storage row.
Every read parsed twice; every write encoded twice.
ZAP Stack: one buffer. Accessors are offset reads. \texttt{Bytes()}
returns the buffer. ZapDB stores the buffer as-is.

\subsection{Signature payload $\leftrightarrow$ transcript $\leftrightarrow$ wire}

Legacy: three marshal passes -- one for the signature payload, one
for the consensus transcript, one for the gossip envelope.
ZAP Stack: one byte stream feeds three orthogonal operations --
\texttt{sha256} for identity, \texttt{TupleHash256} over typed offsets
for the transcript, and \texttt{ecdsa(sha256(unsigned))} for the
signature.

\subsection{Tx envelope $\leftrightarrow$ kind dispatch $\leftrightarrow$ executor visitor}

Legacy: \texttt{tx.Visit(v UnsignedTxVisitor)} -- type-switch on Go
interface assertions in generated code.
ZAP Stack: \texttt{TxKind} is the first byte; executor is a
\texttt{map[TxKind]Handler}. Value-based dispatch on a buffer byte.

\subsection{Block $\leftrightarrow$ proposervm wrapper $\leftrightarrow$ chain-VM block bytes}

Legacy: proposervm wrapped every chain-VM block in its own envelope
with its own signature.
ZAP Stack: the proposer's signature is a leg of the QuasarCert, not a
separate envelope.

\subsection{Mempool $\leftrightarrow$ chain $\leftrightarrow$ network gossip}

Legacy: gossip wire, mempool struct, chain bytes -- three
representations.
ZAP Stack: the same buffer that arrives over the wire goes into the
mempool by reference, lands in a block by reference, and persists to
ZapDB by reference.

\subsection{Validator $\leftrightarrow$ delegator $\leftrightarrow$ L1-staker}

Legacy: three state tables with three marshalled structures and
three executor paths.
ZAP Stack: one ZAP wire format with a \texttt{StakerKind}
discriminator. One table. One executor path.

\subsection{P-chain $\leftrightarrow$ X-chain $\leftrightarrow$ EVM $\leftrightarrow$ chains-VM primitives}

Legacy: each VM had its own copy of \texttt{UTXO},
\texttt{OutputOwners}, \texttt{Credential}, \texttt{BaseTx}.
ZAP Stack: \texttt{luxfi/utxo/wire/} is the single source of truth.
P-chain (LP-023), X-chain (LP-184), EVM internal (LP-185), and the
chains-VM family (LP-186) all consume the same nine migrated fxs:
\texttt{secp256k1fx}, \texttt{nftfx}, \texttt{propertyfx},
\texttt{ed25519fx}, \texttt{mldsafx}, \texttt{slhdsafx},
\texttt{secp256r1fx}, \texttt{pqfx}, \texttt{vrffx}.

\subsection{Consensus transcript $\leftrightarrow$ wire envelope}

Legacy: separately marshalled transcript re-derived at every hop.
ZAP Stack: the transcript function reads typed fields directly from
the ZAP buffer.

\subsection{Codec.Manager $\leftrightarrow$ Sign $\leftrightarrow$ Verify}

Legacy: \texttt{codec.Manager} was a runtime registry of versioned
type-codec pairs; every Sign and Verify call paid a registry lookup
and a reflective marshal.
ZAP Stack: compile-time schemas declared in
\texttt{pkg/wire/zap/schemas.go}. Sign and Verify read offsets
directly. No runtime registry. No reflection. Versioning lives in the
schema kind byte.

\subsection{Genesis $\leftrightarrow$ block $\leftrightarrow$ state $\leftrightarrow$ gossip}

Legacy: four distinct codecs kept in sync by hand.
ZAP Stack: one wire codec across all of them. A genesis is a ZAP
buffer; a block is a ZAP buffer; a state row is a ZAP buffer; a
gossip message is a ZAP buffer. Same parser, same writer, same
identity function.
