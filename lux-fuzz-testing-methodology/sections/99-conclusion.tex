\section{Conclusion}


Property-based testing and fuzzing are the most cost-effective techniques for finding
bugs in cryptographic code. They require minimal setup---write a property, run the
fuzzer---and find bugs that unit tests and code review miss. Our methodology, applied to
Lux Network's cryptographic stack (Go NTT, polynomial arithmetic, FHE, smart contracts),
found 23 bugs including 3 critical issues.

The key insight: write properties, not test cases. A property like ``NTT round-trip is
identity'' tests more effectively than a thousand hand-picked test vectors, because the
fuzzer explores the input space guided by code coverage rather than human intuition.

Start with the round-trip property. If your code has an encode/decode, encrypt/decrypt,
or NTT/INTT pair, write the round-trip fuzz test first. It takes five minutes and catches
the most common class of bugs.
