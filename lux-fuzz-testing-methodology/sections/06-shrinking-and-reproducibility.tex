\section{Shrinking and Reproducibility}


When a fuzzer finds a failing input, it is typically large and random. \emph{Shrinking}
reduces the input to the smallest value that still triggers the failure.

Go's fuzzer performs automatic shrinking: it binary-searches the input space for simpler
inputs that still fail. Foundry does the same. The result is a minimal reproducer that
is easy to understand and debug.

All failing inputs are saved to the corpus directory. Running the test suite without the
\texttt{-fuzz} flag replays all corpus entries, ensuring that regressions are caught
immediately.

\begin{lstlisting}[language=bash,caption={Corpus directory structure}]
testdata/fuzz/FuzzNTTRoundTrip/
    corpus/
        seed_0              # Initial seed
        seed_1              # Another seed
        abc123def456...     # Auto-generated corpus entry
    failing/
        xyz789...           # Minimized failing input
\end{lstlisting}
