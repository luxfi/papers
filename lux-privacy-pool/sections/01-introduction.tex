\section{Introduction}


Blockchain transaction privacy and regulatory compliance have been viewed as fundamentally opposed goals. Privacy-preserving protocols like Tornado Cash \cite{pertsev2019tornado} provide strong anonymity but make it impossible to distinguish legitimate privacy-seeking users from money launderers. This led to regulatory action, including OFAC sanctions against Tornado Cash addresses \cite{ofac2022tornado}.

Privacy Pools, proposed by Buterin, Illum, Nazeri, Wahrstatter, and Jain \cite{buterin2023privacy}, offer a middle path: users can prove their deposits belong to a curated set of compliant addresses (the ``association set'') without revealing which specific deposit they are withdrawing. This preserves transaction privacy within the compliant set while allowing regulators to verify that funds did not originate from sanctioned sources.

Lux Privacy Pools adapt this framework to the Lux Network with the following innovations:

\begin{enumerate}[label=(\roman*)]
    \item \textbf{Multi-chain privacy}: Privacy pools span multiple Lux appchains via Warp Messaging, enabling cross-chain private transfers.
    \item \textbf{BLS12-381 integration}: Groth16 proofs verified via Lux's native BLS12-381 precompile at 326,000 gas.
    \item \textbf{Association Set Providers (ASPs)}: A decentralized marketplace of compliance oracles producing signed association sets.
    \item \textbf{Tiered privacy}: Multiple association set granularities from ``all non-sanctioned'' (maximum privacy) to ``KYC-verified'' (maximum compliance).
    \item \textbf{Incremental Merkle tree}: Efficient deposit accumulation supporting millions of deposits with $O(\log n)$ proof size.
\end{enumerate}
