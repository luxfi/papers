\section{Protocol}

\label{sec:protocol}
%% ============================================================================

Quasar consensus proceeds in three phases for each block height $h$.

\subsection{Phase 1: Photon (Proposal Emission)}

The designated leader for height $h$ (selected by round-robin over the
validator set, rotated each epoch) constructs a block $B_h$ containing:
\begin{itemize}[leftmargin=2em]
\item The parent block hash $H(B_{h-1})$.
\item A batch of transactions from the mempool.
\item The leader's BLS signature over $B_h$.
\item A timestamp $\tau_h$.
\end{itemize}
The leader broadcasts $\langle \textsc{Propose}, B_h \rangle$ to all
validators. Photon emission is fire-and-forget: the leader does not wait
for acknowledgments.

\subsection{Phase 2: Wave (Fast Probabilistic Consensus)}

Upon receiving a valid proposal, each validator $v_i$ enters the Wave phase.
Wave implements Fast Probabilistic Consensus (FPC) with phase-dependent
thresholds.

\begin{definition}[FPC Threshold Selection]
\label{def:fpc}
For round $r$ with sample size $k$, the threshold $\alpha_r$ is:
\[
\alpha_r = \left\lceil \theta_r \cdot k \right\rceil
\]
where $\theta_r \in [\theta_{\min}, \theta_{\max}]$ is selected by a
pseudorandom function:
\[
\theta_r = \theta_{\min} + (\theta_{\max} - \theta_{\min}) \cdot
\frac{\mathrm{SHA256}(\mathit{seed} \mathbin\| r) \bmod 2^{16}}{2^{16}}
\]
Default parameters: $\theta_{\min} = 0.5$, $\theta_{\max} = 0.8$.
\end{definition}

In each round $r = 1, 2, \ldots$, validator $v_i$:
\begin{enumerate}[leftmargin=2em]
\item Samples $k$ validators uniformly at random.
\item Queries each for their current preference on $B_h$.
\item If $\geq \alpha_r$ responses favor $B_h$, sets preference to accept;
      otherwise sets preference to reject.
\item Increments a confidence counter if preference matches the previous round;
      resets it otherwise.
\item If confidence reaches $\beta$, transitions to the Quasar phase with
      preference locked.
\end{enumerate}

\begin{algorithm}
\caption{Wave: FPC voting round}
\label{alg:wave}
\begin{algorithmic}[1]
\Require Validator $v_i$, block $B_h$, round $r$, sample size $k$
\State $S \gets \text{SamplePeers}(k)$
\State $\alpha_r \gets \lceil \text{FPCThreshold}(r, k) \rceil$
\State $\mathit{votes} \gets 0$
\For{$v_j \in S$}
    \State $\mathit{votes} \gets \mathit{votes} + \text{QueryPreference}(v_j, B_h)$
\EndFor
\If{$\mathit{votes} \geq \alpha_r$}
    \State $\mathit{pref}_i \gets \textsc{Accept}$
\Else
    \State $\mathit{pref}_i \gets \textsc{Reject}$
\EndIf
\If{$\mathit{pref}_i = \mathit{prevPref}_i$}
    \State $\mathit{confidence}_i \gets \mathit{confidence}_i + 1$
\Else
    \State $\mathit{confidence}_i \gets 0$
\EndIf
\If{$\mathit{confidence}_i \geq \beta$}
    \State \textbf{enter} Quasar phase with $\mathit{pref}_i$
\EndIf
\end{algorithmic}
\end{algorithm}

\subsection{Phase 3: Quasar (DAG Finalization with Quasar Certificate)}

Once a validator locks its preference, it enters the Quasar phase and produces
a quantum signature on the block:

\begin{enumerate}[leftmargin=2em]
\item \textbf{BLS}: Sign $H(B_h)$ with $\mathit{sk}_i^{\mathrm{BLS}}$.
      Produces a 96-byte $\mathbb{G}_2$ signature.
\item \textbf{Ringtail}: Contribute share $\sigma_i^{\mathrm{RT}}$ to the
      threshold signing of $H(B_h)$ using $\mathit{sk}_i^{\mathrm{RT}}$.
\item \textbf{ML-DSA-65}: Sign $H(B_h)$ with $\mathit{sk}_i^{\mathrm{ML}}$.
      Produces a 3{,}309-byte signature.
\end{enumerate}

All three operations execute in parallel. The validator broadcasts
$\langle \textsc{QuasarVote}, i, \sigma_i^{\mathrm{BLS}},
\sigma_i^{\mathrm{RT}}, \sigma_i^{\mathrm{ML}} \rangle$.

\begin{definition}[Quasar Certificate]
A Quasar certificate $\mathcal{C}_h$ for block $B_h$ consists of:
\begin{itemize}[leftmargin=2em]
\item $\sigma^{\mathrm{BLS}}_{\mathrm{agg}}$: An aggregate BLS signature from
      $\geq 2f+1$ validators (48 bytes after aggregation).
\item $\sigma^{\mathrm{RT}}$: A Ringtail threshold signature from $\geq t$
      share contributors (variable size, $\approx 56$\,KB for $N=256$).
\item $\{\sigma_i^{\mathrm{ML}}\}_{i \in Q}$: A set of $\geq 2f+1$ ML-DSA-65
      signatures (each 3{,}309 bytes).
\end{itemize}
$B_h$ is finalized when $\mathcal{C}_h$ contains valid signatures from all
three layers with quorum sizes $\geq 2f+1$.
\end{definition}

A block proposer that collects $\geq 2f+1$ votes across all three layers
constructs $\mathcal{C}_h$, aggregates the BLS signatures, and broadcasts
$\langle \textsc{Finalize}, B_h, \mathcal{C}_h \rangle$. Any validator
can verify $\mathcal{C}_h$ by checking:
\begin{enumerate}[leftmargin=2em]
\item $\mathrm{BLS.Verify}(\mathit{pk}^{\mathrm{BLS}}_{\mathrm{agg}},
      \sigma^{\mathrm{BLS}}_{\mathrm{agg}}, H(B_h))$ --- one pairing check.
\item $\mathrm{RT.Verify}(\mathit{pk}^{\mathrm{RT}}, \sigma^{\mathrm{RT}},
      H(B_h))$ --- one matrix-vector multiplication and one hash.
\item For each $i \in Q$: $\mathrm{MLDSA.Verify}(\mathit{pk}_i^{\mathrm{ML}},
      \sigma_i^{\mathrm{ML}}, H(B_h))$.
\end{enumerate}

\subsection{Epoch Rotation}

Quasar groups blocks into epochs of fixed length $E$. At epoch boundaries:
\begin{itemize}[leftmargin=2em]
\item Validator sets may change (additions, removals, stake changes).
\item Ringtail threshold keys are reshared via a distributed key generation
      (DKG) round.
\item Epoch certificates summarize the finalized chain state.
\item Epochs older than 6 are pruned from active memory; only epoch
      certificates are retained.
\end{itemize}
The 6-epoch retention window bounds active memory to $O(6 \cdot E \cdot n)$
regardless of total chain length.
