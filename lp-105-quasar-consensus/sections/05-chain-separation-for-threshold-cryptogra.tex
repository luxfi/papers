\section{Chain Separation for Threshold Cryptography}

\label{sec:chain-sep}
%% ============================================================================

The Lux primary network distributes threshold cryptographic operations
across four chains.  Each chain runs exactly one class of protocol.
This separation enforces the principle: \emph{consensus signing
(Q-Chain) never shares state or key material with general-purpose MPC
(T-Chain)}.

\begin{table}[ht]
\centering
\small
\begin{tabular}{@{}llp{6.8cm}@{}}
\toprule
\textbf{Chain} & \textbf{Threshold Role} & \textbf{Detail} \\
\midrule
X-Chain & Verification only &
  Verifies already-signed UTXOs via Fx credential plugins
  (secp256k1, Ed25519, Ringtail, ML-DSA).  No signing ceremonies. \\[3pt]
Q-Chain & Ringtail 2-round consensus &
  Runs the Ringtail lattice-based threshold protocol
  (Module-LWE, $t$-of-$n$, 2 rounds) to produce the post-quantum
  consensus signature $\sigma_{\mathrm{RT}}$.  Does \emph{not} run
  CGGMP21, FROST, or general MPC. \\[3pt]
T-Chain & All MPC ceremonies &
  Runs CGGMP21 (threshold ECDSA), FROST (threshold Schnorr),
  Ringtail (for cross-chain custody, distinct key material from Q-Chain),
  and TFHE (threshold FHE) for bridge custody and encrypted
  computation. \\[3pt]
Z-Chain & ZKP aggregation &
  Each validator signs with ML-DSA-65 (FIPS 204).  Z-Chain aggregates
  $N$ ML-DSA identity signatures into a single 192-byte Groth16 proof
  $\pi_{\mathrm{ZK}}$.  Also serves as rollup substrate. \\
\bottomrule
\end{tabular}
\caption{Per-chain threshold cryptographic responsibilities.}
\label{tab:chain-sep}
\end{table}

\subsection{Rationale}

\paragraph{X-Chain: verification only.}
X-Chain processes UTXO transfers.  It must verify signatures from
multiple cryptographic families (classical and PQ) but never initiates
threshold signing.  The Fx plugin architecture dispatches verification
to the appropriate algorithm based on the credential type attached to
the UTXO.

\paragraph{Q-Chain: Ringtail consensus only.}
Q-Chain is the consensus chain.  Its sole threshold operation is
producing the Ringtail signature $\sigma_{\mathrm{RT}}$ that attests
validator agreement.  Restricting Q-Chain to a single protocol
minimizes attack surface and simplifies formal analysis: the only
interactive subprotocol running during consensus is Ringtail's 2-round
protocol.

\paragraph{T-Chain: general MPC.}
Bridge custody, cross-chain signing, and encrypted computation require
CGGMP21 (for secp256k1 chains), FROST (for Ed25519 chains), Ringtail
(for PQ custody, separate key material from Q-Chain consensus keys),
and TFHE (for confidential smart contracts).  These are computationally
heavier and have different liveness requirements than consensus.
Isolating them on T-Chain prevents an MPC ceremony stall from blocking
consensus.

\paragraph{Z-Chain: ZKP aggregation.}
ML-DSA-65 signatures are 3{,}309 bytes each.  With $n = 100$
validators, raw ML-DSA attestation would cost 330{,}900 bytes per
block.  Z-Chain runs a Groth16 prover that takes as public input the
set of validator public keys and the block hash, and as witness the $n$
individual ML-DSA signatures.  The resulting proof $\pi_{\mathrm{ZK}}$
is 192 bytes regardless of $n$.

\subsection{Per-Block Production Flow}
\label{sec:per-block}

All three cryptographic paths execute in parallel for each block $B$:

\begin{enumerate}[nosep]
  \item \textbf{Q-Chain (Ringtail)}: Validators run Ringtail Round~1
    (commitment shares), then Round~2 (response shares).  The combiner
    produces $\sigma_{\mathrm{RT}}$.  Wall-clock: ${\sim}55$\,ms
    (48\,ms network + 7\,ms combination).
  \item \textbf{BLS aggregation}: Each validator signs $H(B)$ with
    BLS12-381.  The proposer aggregates into a single 48-byte
    $\sigma_{\mathrm{BLS}}$.  Wall-clock: ${\sim}3$\,ms (GPU) or
    ${\sim}100$\,ms (CPU).
  \item \textbf{Z-Chain (Groth16)}: Each validator signs $H(B)$ with
    ML-DSA-65 (measured ${\sim}495$\,$\mu$s per validator, ${\sim}181$\,$\mu$s
    verify; see Apple~M1~Max benchmarks in \texttt{consensus/BENCHMARKS.md}).
    Z-Chain collects signatures and produces $\pi_{\mathrm{ZK}}$ via Groth16.
    Wall-clock of the prover: ${\sim}400$\,ms CPU or ${\sim}5$--$15$\,ms GPU
    for the full ML-DSA-65 verification circuit ($\approx 2^{22.5}$ R1CS
    constraints per verification; see Appendix~B of
    \texttt{proofs/quasar-cert-soundness.tex}). Proof size is $192$\,B
    independent of the circuit.
\end{enumerate}

The block is finalized when all three components are available.
\[
  \mathsf{QuasarCert}(B) =
  (\sigma_{\mathrm{RT}},\; \sigma_{\mathrm{BLS}},\; \pi_{\mathrm{ZK}})
\]
