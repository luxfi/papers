\paragraph{What did not change.}
The 3.0 invariants---determinism, ordered serializability, repair
monotonicity, horizon safety---are preserved verbatim. The wire format
(\texttt{QuasarRoundDescriptor}, \texttt{QuasarRoundResult}) is
byte-for-byte unchanged. The public host API
(\texttt{QuasarGPUEngine}~\cite{lp132-quasarexec}) is unchanged. The
canonical-order $\preceq_{\mathrm{can}}$ is unchanged: 4.0 reads
3.0-emitted round artifacts and emits 4.0 round artifacts with the
extra \texttt{hint\_roots}~\cite{chiron2025} riding in the existing
\texttt{roots} slot. There is no on-disk state migration. Validators
running 3.0 after 2026-02-14 are rejected at the consensus engine and
must upgrade.

\paragraph{Backward / forward compatibility.}
\begin{itemize}[leftmargin=2em]
\item \texttt{ServiceId.Count} flips from 12 to 16 at the activation
      height; old IDs unchanged.
\item \texttt{VersionBlock.MAX\_INLINE\_VERSIONS} flips from 4 to 8;
      4.0 reads 3.0 blocks, 3.0 cannot read 4.0 blocks (forward only).
\item The HMAC-keccak verifier path is preserved as a
      development-only mode under \texttt{EVM\_DEV\_HMAC\_VERIFIER=1}
      for deterministic test vectors. It is rejected on production
      networks.
\item Pre-activation rounds remain valid as historical 3.0 rounds; the
      activation height is the partition.
\end{itemize}
