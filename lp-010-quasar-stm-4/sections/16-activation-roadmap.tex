\subsection{Activation height}

QuasarSTM~4.0 activated on Lux mainnet at \textbf{2026-02-14, 17:00
UTC}. The activation predicate is
\[
\mathit{quasar.execution\_version} \geq 4
\]
in the Quasar consensus engine (LP-020). Wave-tick rounds emitted with
$\mathit{execution\_version} < 4$ after the activation height are
rejected.

Validators upgraded across the preceding week:

\begin{itemize}[leftmargin=2em]
\item \textbf{2026-02-07}: spec freeze; \texttt{cevm} v0.41--v0.49
      milestone train feature-complete on \texttt{main}.
\item \textbf{2026-02-08 to 2026-02-13}: staged validator rollout;
      $\geq 80\%$ stake on 4.0 by 2026-02-13~18:00~UTC.
\item \textbf{2026-02-14 17:00~UTC}: hard activation. 4.0 becomes the
      only valid execution version.
\end{itemize}

\subsection{Migration steps for validators}

\begin{enumerate}[leftmargin=2em]
\item Upgrade \texttt{cevm} to a release built from \texttt{cevm}
      $\geq$ v0.49.
\item Re-roll the Quasar consensus engine binary (LP-020) with
      \texttt{execution\_version=4} support.
\item Verify the cert verifier table at engine creation; on production
      networks the verifier table must be \texttt{kProdVerifiers}
      (\S\ref{sec:verifiers}). The \texttt{EVM\_DEV\_HMAC\_VERIFIER}
      flag is rejected at startup.
\item Run \texttt{cevm-genesis-replay} against the latest 3.0 round to
      confirm byte-identical roots before publishing.
\item Publish on the validator gossip channel and join 4.0 round
      production.
\end{enumerate}

There is no on-disk state migration. 4.0 reads 3.0 round artifacts as
historical 3.0 rounds; new rounds emitted post-activation are 4.0
rounds.

\subsection{Migration steps for app developers}

\begin{enumerate}[leftmargin=2em]
\item Recompile contracts against the 4.0 EVM (175 opcodes); contracts
      that compiled against 3.0 (118 opcodes) are forward-compatible.
\item Adopt the Solidity \texttt{lane\_class} attribute on hot state
      variables to opt into the AdaptiveSchedule fast path
      (\S\ref{sec:conflictspec}). Without the attribute, the predictor
      and historical sources still apply; the attribute adds a
      higher-priority \texttt{Static} source.
\item For DEX-style hot lanes (fee accumulators, order-book levels),
      adopt the \texttt{Commutative} class to route writes through
      Tier~3 reducers (\S\S\,\ref{sec:tier3}, \ref{sec:laneclass}).
\item Re-run integration tests against the cross-backend determinism
      harness (\S\ref{sec:determinism}); contracts that produce
      identical roots in both backends are 4.0-clean.
\end{enumerate}

\subsection{Out of scope for 4.0 (5.0 research)}

\begin{itemize}[leftmargin=2em]
\item Multi-GPU MVCC over RDMA.
\item Operation-window validation for pathological long transactions.
\item Formal proof of kernel refinement against the abstract
      semantics. (4.0 ships the abstract semantics and the
      differential fuzzer; the proof is 5.0.)
\item Distributed CSMV commit server. (4.0 ships the single-GPU
      scaffold.)
\item 800G InfiniBand / GPUDirect cell topologies.
\end{itemize}

These are tracked under a separate \emph{QuasarSTM 5.0 research} document
that does not touch the 4.0 production specification.
