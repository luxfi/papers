### WARNINGS

**W-01. DAG-EVM `serializability` theorem is trivially true.**

`DAGEVM.lean:276` proves serializability by returning `L` itself: `exact <L, Perm.refl L, rfl>`. This says "there exists a permutation that produces the same state" by choosing the identity permutation. It proves nothing beyond what the type signature already states. The intended claim (every topo order is equivalent to a *specific canonical linear order*) is not formalized.

**W-02. PQZParallel.lean theorems are vacuously true.**

`productSafety` (line 113) is `Iff.rfl` -- it proves `P iff P`. `noCrossChainConflict`, `independentFinality`, `validatorNonInterference`, `pqzScalability` all prove `True := trivial`. The type-level isolation argument documented in the comments is sound conceptually, but none of these theorems carry any proof content. They are documentation, not proofs. The README counts them toward the "72 proofs" total.

**W-03. `parallel_verify_sound` wrapper theorem in DAGZChain has a local `verifyBatch` that shadows the axiom.**

Line 245 defines a local `verifyBatch` as `fun _ _ => True` which makes the theorem trivially true regardless of the axiom. The wrapper proves `forall p, verify ... <-> True` effectively. The axiom `batch_sound` itself has `sorry` in its `where` clause. Neither the axiom nor the theorem carries real proof content.

**W-04. Paper S6 line count references are stale.**

`dag-evm-formal.tex` S3 proof says "Full proof in `Consensus/DAGEVM.lean:60--135`." The actual `nonConflict_commute` theorem spans lines 111--163. Line references have drifted.

**W-05. Hanzo lakefile.lean duplicates Consensus/Crypto/Trust/Warp/Network libs from Lux.**

The `hanzo/proofs/lean/lakefile.lean` declares its own `Consensus`, `Crypto`, `Trust`, `Warp`, `Network`, `GPU` libs with roots identical to the Lux lakefile. These are labeled "Infrastructure proofs (from Lux L1 foundation)" but are separate copies, not dependencies. If the Lean files drift between repos, the proofs diverge silently. Should be a `require luxFormal` dependency instead.

**W-06. Anchor paper precompile address is 0x0700...10 but paper does not appear in the precompile registry.**

The paper (`lp-checkpoint-anchor.tex`) specifies address `0x0700...10`. The precompile registry README at `lux/precompile/README.md` lists babyjubjub at `0x0500..07` but no anchor precompile is shown. Verify whether the anchor precompile is actually deployed or still spec-only.

**W-07. BabyJubjub Lean proof is entirely axiom-based.**

Every property (`edwards_add_total`, `edwards_add_comm`, `edwards_add_identity`, `scalar_mul_*`, `cofactor_clear`, `eddsa_correctness`, `eddsa_unforgeability`) is declared as `axiom`. The only proved theorems are trivial gas bound checks (`omega`). This is an axiom catalog, not a proof. The README counts it in the "72 proofs" total.

**W-08. `lux-governance-dao.tex` contains "Backwards Compatibility" section header.**

Line 1082 has `## Backwards Compatibility`. This survived cleanup. The precompile-babyjubjub reference to "Backwards Compatibility" (line 112) is legitimate -- it refers to EIP-2494 section name.

Pick one source of truth (the code) and update the Lean constants and paper S5 text to match. The paper's own table already agrees with code -- only the prose and Lean are stale.

3. **E-04: Add missing lean_lib entries to lakefile.** 9 Lean files on disk are unreachable by `lake build`. They are not being type-checked. Add `GPU`, `Vault` libs and extend `Bridge` roots. Until then, these files could contain arbitrary `sorry` or type errors with no CI signal.
