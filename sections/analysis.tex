\section{Analysis}
\label{sec:analysis}

\subsection{Safety}

\begin{theorem}[Safety]
If two correct validators decide on conflicting values, the probability of disagreement is bounded by:
\begin{equation}
    P(\text{disagreement}) \leq 2^{-\Omega(\beta)}
\end{equation}
where $\beta$ is the conviction threshold, assuming $f < n\alpha - k/2$ Byzantine validators.
\end{theorem}

\textit{Proof sketch.} Once a correct validator accumulates $\beta$ consecutive $\alpha$-majority rounds for color $c$, any other correct validator would need to observe $\beta$ consecutive rounds for color $\bar{c}$. With $\alpha > 1/2$, the probability that a random sample returns different $\alpha$-majorities to two honest validators decreases exponentially with $k$. The conviction counter requires this to occur $\beta$ consecutive times, yielding the exponential bound. \qed

\subsection{Liveness}

\begin{theorem}[Liveness]
Under partial synchrony, all correct validators eventually decide within $O(\log n)$ rounds in expectation, assuming $f < S/4$ adversarial stake.
\end{theorem}

\textit{Proof sketch.} Consider the ``undecided'' fraction of correct validators. In each round, a validator with a minority color switches to the majority color with probability $\geq 1 - 2^{-\Omega(k)}$. By a multiplicative drift argument, the minority fraction halves each round in expectation, yielding $O(\log n)$ rounds until all correct validators share the same color. The conviction counter then triggers decision after $\beta$ additional rounds. \qed

\subsection{Message Complexity}

Each round, every validator sends $k$ query messages and receives $k$ responses:
\begin{equation}
    \text{Messages per round} = 2kn
\end{equation}

With $O(\log n)$ expected rounds:
\begin{equation}
    \text{Total messages} = O(kn \log n)
\end{equation}

This is a substantial improvement over classical BFT ($O(n^2)$ per decision) and enables scaling to thousands of validators.

\subsection{Parameterization}

The security parameter $k$ (sample size) controls the tradeoff between security and performance:

\begin{itemize}
    \item \textbf{$k = 20$}: Standard configuration. Achieves $2^{-32}$ disagreement probability with $\beta = 20$.
    \item \textbf{$\alpha = 0.6$--$0.8$}: Controls sensitivity. Higher $\alpha$ provides stronger guarantees but slower convergence.
    \item \textbf{$\beta = 15$--$30$}: Conviction threshold. Higher $\beta$ strengthens safety at the cost of latency.
\end{itemize}

These parameters are tunable per-chain, allowing X-Chain to optimize for throughput (lower $\beta$) while P-Chain optimizes for safety (higher $\beta$).
