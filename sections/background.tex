\section{Background and Related Work}
\label{sec:background}

\subsection{Classical BFT Protocols}

Practical Byzantine Fault Tolerance (PBFT) \citep{castro1999practical} achieves consensus in $O(n^2)$ messages with deterministic finality, tolerating $f < n/3$ Byzantine faults. Variants such as Tendermint \citep{buchman2016tendermint} and HotStuff \citep{yin2019hotstuff} reduce communication to $O(n)$ per round via leader-based proposals and threshold signatures, but still require a designated leader and suffer from leader bottlenecks at scale.

\subsection{Nakamoto Consensus}

Bitcoin's proof-of-work consensus \citep{nakamoto2008bitcoin} achieves probabilistic finality through computational puzzles. The longest-chain rule provides Sybil resistance but introduces latency: six confirmations (~60 minutes) for practical security. Proof-of-stake variants (Ethereum 2.0, Cardano) reduce energy consumption but retain the fundamental latency-throughput tradeoff.

\subsection{DAG-Based Protocols}

Directed Acyclic Graph (DAG) structures improve throughput by processing multiple transactions concurrently. IOTA's Tangle uses tip selection algorithms but lacks formal finality guarantees. Hashgraph achieves asynchronous BFT consensus on a DAG but requires $O(n^2)$ gossip. PHANTOM and SPECTRE provide DAG-based ordering with provable security but at significant protocol complexity.

\subsection{Metastable Consensus}

The metastable approach was introduced by the Snow protocol family. Unlike all prior approaches, Snow protocols achieve consensus through repeated random sub-sampling without leader election, committee selection, or proof-of-work. This yields $O(kn \log n)$ message complexity for security parameter $k$, enabling both fast finality and large validator sets.

Lux builds upon and extends this foundation with:
\begin{itemize}
    \item Stake-weighted sampling for Sybil resistance in permissionless settings
    \item DAG-based transaction structure for throughput amortization
    \item Multi-chain architecture for workload isolation
    \item Formal parameterization linking security parameter $k$ to Byzantine tolerance
\end{itemize}
