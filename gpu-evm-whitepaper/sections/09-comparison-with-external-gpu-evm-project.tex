\section{Comparison with External GPU EVM Projects}

\label{sec:comparison}
%% ============================================================================

Several projects have explored GPU-accelerated EVM execution. We compare cevm against
the most relevant:

\subsection{CuEVM (FaceBlockTeam/gpuEVM)}

CuEVM~\cite{cuevm} is a CUDA-based GPU EVM implementation using CGBN (Cooperative Groups
Big Number) for 256-bit arithmetic. Key characteristics:

\begin{itemize}
\item \textbf{Backend}: CUDA only (NVIDIA GPUs). Uses cooperative groups for 256-bit
      integer operations, requiring warp-level synchronization.
\item \textbf{Performance}: 60--100K TPS experimental, primarily benchmarked on simple
      transfer workloads.
\item \textbf{Target}: Designed for EVM fuzzing and testing, not production block execution.
      Lacks conflict detection (no Block-STM or equivalent).
\item \textbf{State}: No GPU-resident state---state is transferred from CPU per block.
\end{itemize}

\subsection{GatlingX}

GatlingX~\cite{gatlingx} claims 200$\times$ speedup for GPU-accelerated EVM but provides
no reproducible benchmarks, no open source implementation, and no peer-reviewed evaluation.
We do not consider unverifiable claims.

\caption{Feature comparison of GPU EVM implementations. cevm ships three backends

The key novelty of cevm is \textbf{Metal Block-STM on GPU}: no published work combines
the Block-STM optimistic concurrency protocol~\cite{blockstm} with GPU execution. CuEVM
executes transactions independently without conflict detection, which is sufficient for
fuzzing but not for production block processing where transactions share state.

\textbf{Key observations:}
\begin{itemize}
\item cevm C++ matches pevm Rust on EVM-only throughput ($\sim$20\,Ggas/s vs 19--22\,Ggas/s),
      confirming that the execution engine is not the differentiator at this performance level.
\item cevm's GPU acceleration (4.85$\times$) applies \emph{on top of} the C++ interpreter,
      targeting the opcode dispatch that C++ and Rust handle equally well.
\item The real differentiator is the GPU pipeline: crypto offloading (ecrecover, Keccak-256,
      PQ signatures) addresses the 87\% of time that pure interpreter optimization cannot touch.
\item CuEVM's lack of conflict detection limits it to embarrassingly parallel workloads
      (fuzzing, independent transfers). cevm's GPU Block-STM handles real-world DeFi workloads
      with shared state.
\end{itemize}
