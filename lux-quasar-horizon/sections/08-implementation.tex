\subsection{The Quasar engine flow}

\begin{itemize}[leftmargin=2em,nosep]
  \item Photons (validator votes) arrive over the Lumen transport (forthcoming Lumen LP). The transport is ZAP \cite{lp020} (zero-copy wire protocol; not p2p / gRPC).
  \item Wave threshold-voting runs per-vertex on the DAG frontier (\texttt{protocol/wave}). Vertices that gather $\geq 2/3$-weight Wave votes become Wave-final.
  \item Focus tracks consecutive-successes counters for each vertex; once Focus's $\beta$ threshold is met, the vertex is Focus-final (\texttt{protocol/focus}).
  \item The DAG safe-prefix commit (\texttt{protocol/field} / \texttt{protocol/nebula}) collects Focus-final vertices into a bundle; the bundle root is the canonical NebulaRoot.
  \item The BLS Beam aggregates over the bundle's $\geq 2/3$-weight signers. Bundle moves to Beam-final.
  \item The ML-DSA cert set assembles per-validator FIPS-204 attestations over the same NebulaRoot transcript $\tau$. Bundle moves to PQ-attested.
  \item The Pulsar engine signs $\tau$ via Sign1/Sign2/Combine under the active key era's GroupKey. Bundle moves to Pulse-sealed.
  \item Prism (\texttt{protocol/quasar/horizon.go}) verifies the composite. Bundle moves to Horizon-final.
\end{itemize}

\subsection{Quasar certificate}

The on-wire \texttt{QuasarCert} (the Horizon composite, with the legacy Quasar 3.0 type name retained for compatibility) is at \texttt{protocol/quasar/types.go:40}:

\begin{verbatim}
type QuasarCert struct {
    BLS        []byte  // BLS12-381 aggregate, 48 bytes
    Pulsar   []byte  // Pulsar Pulse (variable size)
    MLDSAProof []byte  // Z-Chain Groth16 over N x ML-DSA, ~192 bytes
    Epoch      uint64
    Finality   time.Time
    Validators int
}
\end{verbatim}

The newer canonical type at \texttt{warp/pulsar/HorizonCertificate} (cf.\ Section~\ref{sec:prism-composition}) carries the explicit transcript-binding fields ($\mathsf{NebulaRoot}$, $\mathsf{KeyEraID}$, $\mathsf{Generation}$, $\mathsf{HashSuiteID}$) introduced in LP-105. Older callers see the legacy three-byte-blob layout; new callers see the explicit-field layout. Both bind to the same canonical $\tau$.

\subsection{Quasar mode toggles}

Each lane is independently toggleable:
\begin{itemize}[leftmargin=2em,nosep]
  \item BLS-only: classical fast path. Beam-final is the strongest state. Used in development and on chains that explicitly accept the classical-only threat model.
  \item BLS + Pulse: dual PQ. Pulse-sealed is the strongest single-lane state. Used when ML-DSA cert-set bandwidth is impractical.
  \item BLS + Pulse + ML-DSA: full Quasar Horizon. The production mode on Lux mainnet.
  \item BLS + Pulse + ML-DSA + Z-Chain Groth16: production mode with succinct ML-DSA cert-set compression. The wrapper is classical (Remark~\ref{rem:groth16-wrapper-horizon}); the underlying PQ root of trust is unchanged.
\end{itemize}

\texttt{IsTripleMode()} on the engine returns true when all three signing layers are configured.

\subsection{Cross-implementation parity}

The Go canonical \cite{consensusgo, ringtailgo, thresholdgo, lensgo, warpgo} is the byte oracle. The C++ port at \texttt{luxcpp/crypto/ringtail/cpp/} \cite{lp137} mirrors the Go canonical layer for layer; KAT vectors gate every release. SDK status (honest assessment): Go is production-ready; Python (\texttt{pkg/python/}) is the only complete non-Go SDK with real consensus logic; C, Rust (FFI wrapper around C), and C++ are at varying levels of completion. We do not ship cross-language production paths beyond Go.

\subsection{Wire transport}

Inter-node communication uses ZAP (\texttt{github.com/luxfi/zap}; LP-022). Not p2p, not gRPC/protobuf. ZAP delivers $\sim 114\,\mathrm{K}$ TPS single-connection, $\sim 376\,\mathrm{K}$ TPS at 20 parallel connections, and $\sim 20.26\,\mathrm{M}$ TPS at 50 connections + batch 1000 (\texttt{bench/}; full numbers in \cite{luxbenchmarks}). The ZAP design is not the focus of this paper; the relevant fact is that Beam aggregation and Pulse signing are not network-bound on Lux mainnet at $n = 21$.
