\begin{abstract}
\noindent We measure the per-polynomial throughput of the canonical
post-quantum NTT used by the Lux Pulsar threshold signature
($R_q = \mathbb{Z}_q[X]/(X^{256}+1)$, $q = 0x1000000004A01$) on Apple
M1 Max across three backends — scalar CPU, Apple Metal, and a WGSL
kernel via the host polyfill — and identify the empirical crossover
where each GPU backend first beats CPU. We find that the CPU baseline
is remarkably flat ($\sim 1.4$ \textmu s per NTT regardless of batch
size); Metal pays a $\sim 1.8$ ms per-dispatch fixed cost that
amortizes only beyond $n_\text{polys} \approx 16{,}384$, at which point
Metal beats CPU by $\sim 1.4\times$ and grows monotonically with batch
size. From these measurements we derive three empirical scaling laws
that govern when GPU acceleration is profitable for blockchain workloads:
(L1) the \emph{batch-size law} — GPU dispatch is fixed-cost per call,
so per-poly speedup scales as $1 - C/n$; (L2) the \emph{validator-
parallelism law} — single-validator workloads rarely cross the
breakeven, but batched aggregation across $k$ validators amortizes
linearly; (L3) the \emph{epoch-amortization law} — workloads that
collect work over an epoch (block, finality round, FHE evaluation)
trade latency for batch size and cross over far earlier than per-tx
operations.
\end{abstract}
